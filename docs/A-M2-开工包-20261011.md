## 4. 开工前必须先处理的三个现实约束

**① 预算只剩 ~184 LUT6（M2 原估 +300~500）——必须先决定怎么腾**

| 资源 | 配额 | M1 已用 | 余量 | M2 需求 | 结论 |
|------|------|---------|------|---------|------|
| LUT6 | 1400 | 1216 | **184** | +300~500 | ❌ 必须砍范围或腾额度 |
| ERAM | 8 | 2 | 6 | 1（每列记忆） | ✅ 够 |
| DSP | 0 | 0 | 0 | 0 | ✅ 必须保持 |

四个选项（建议 **a + c** 组合）：

- **a. 砍 M2 范围（推荐先做）**：**只做"挥手方向"**（完全复用 M1 的质心），指尖/手型等有余量再上 → 需求从 +300~500 降到 **+100~150**，184 勉强够。
- b. 向 C 申请扩容（机动只剩 50；C 自己的配额还有余量）→ 走"提需求"流程。
- c. **在 M1 里省回来**：示教采样密度再降、2 s 闪叠加倒计时简化、交付版关掉调试叠加路径（`MASK_PREVIEW`）→ 约 +100~200。
- d. 用块资源换 LUT：每列记忆走 ERAM（不占 LUT）；任何 `*` 都要复查 DSP。

**② 接口缺口：M2 的结果目前送不到游戏层**
指尖/质心坐标、手势事件要交给像素域（B 的游戏层），但 **CTRL_SYNC 上行字已冻结为 M4c 的判定结果** `{verdict[1:0], viol_cnt[11:0], fill[11:0]}`。
→ **短期不依赖 C**：先用 **DBG 字段**观测（质心 x/y、手型、方向、事件计数），算法验证不需要游戏层；
→ **交付前**：向 C 提"CSI→像素 结果通道"（复用 CTRL_SYNC 上行按模式复用，或加第二个 26 位字）。

**③ M1 的三项验收 + "形态学不做"要同步给 C**（见第 2 节末尾）。

## 5. 怎么做（四轮，一轮一个关注点）

> 节奏（M1 验证有效，必须照做）：**改码 → 完整构建 → 数字写进 `docs/CHANGELOG.md` → 提交 → 上板一轮 → 记录/反馈 → 下一轮**。
> **上下文不够就只做一轮**，绝不一口气写完；每轮结束**都提交**、**都跑完整构建**。

### M2.0 前置（0.5 小时，不写码）
跑完 M1 三项验收（跟手流畅 / 出画 5 帧 · 回画 3 帧 / 人脸干扰），把结果和"形态学不做"写进 `docs/A-进度交接.md`。

### M2.1 挥手方向（1 天）⭐ 建议从这条开始

- **做法**：复用 M1 已经算好的**质心**（`Σ列/Σ行 ÷ 像素数`，S1 已统一观测源）。
  每帧算 `dx = x − x_prev`、`dy = y − y_prev`；用 **3~5 帧滑动窗**累加位移与速度；
  **滞回 + 冷却**（一次事件后约 300 ms 不再触发）防连发。
- **判据（初始值，档位化后可现场调）**：
  - 左挥/右挥：`|Σdx| > |Σdy|` 且 `|Σdx| > VX_TH`，累计符号一致；
  - 下劈：`Σdy > VY_TH` 且 `|Σdy| > |Σdx|`。
- **落点**：`recog_top.v` 内联（不新增文件）；参数走编译期常量 + `recog_algo` 档位（0..15）分档做现场 A/B。
- **成本**：≈100~150 LUT6 + ~60 FF，**0 ERAM / 0 DSP** → 落在 184 余量内。
- **验证**：先只加 DBG 观测（方向 + 事件计数），上板按第 6 节协议做 20 次/方向，正确率 ≥18/20 才算过。

### M2.2 手型 + 指尖（1~1.5 天，先解决预算）

- **每列顶部轮廓记忆**：规划是 1280 列 × 10 bit ≈ 1 块 ERAM。**省钱做法**：照搬示教的"**每 4 列取 1 列**"（M1 用这招省了 ~150 LUT6）→ 320 列 × 10 bit，仍占 1 块 ERAM；4 像素分辨率对"数峰"和刀尖足够。
- **扫描范围**：只在**上一帧包围盒 ± 余量**内（和 ROI 门控共用窗口逻辑），不要全帧。
- **峰数判定**：对轮廓高度序列求局部极大值个数 → **≥2 峰 = 张开，1 峰 = 握拳**；连续 N 帧一致才改状态（滞回，照 `HOLD_FRAMES`/`LOCK_FRAMES` 的写法）。
- **指尖坐标** = 最高峰的列 x 与该列顶部 y。
- **成本**：150~250 LUT6 → **必须先按第 4 节腾出额度**。
- **验证**：张开/握拳各 20 次看状态稳定不抖；把准星临时换成"指尖点"，目视核对指尖是否落在手指尖。

### M2.3 结果外送 + 联调（0.5 天，依赖 C）
向 C 提通道需求（第 7 节第 2 条）→ 把 `{有效, x[11:0], y[10:0]}`（或按模式复用的上行字）送到像素域 → 与 B 的 M3 联调（B 的输入抽象层已预留）。

### M2.4 收尾
完整构建 + 门禁核对 + 记录（A 线累计 LUT6/ERAM/DSP/WNS）+ tag + 交 C 合并 → 按用户指示更新 PR。

## 6. 上板验收协议（"挥手 >90%" 怎么测才算数）

1. 固定条件：摄像头位置/距离固定、室内光不变、演示者穿短袖；
2. 每个方向做 **20 次**（左挥 / 右挥 / 下劈），每次间隔 ≥1 s（避开冷却窗）；
3. 用 DBG 的"方向 + 事件计数"字段对数：**正确 ≥18/20** 才算过；
4. 同时记录**误触发**次数（没挥手却报事件）；
5. 数据格式写进 `docs/CHANGELOG.md`：日期 / 提交 / 配置 / slices·LUT6·ERAM·DSP·WNS·feedthrough / 是否一次 PnR / bit 路径 + SHA256 / 场景与结论。

## 7. 需要向 C 提的三件事（M2 开工就发）

1. **DBG 字段**：质心 x/y、手型、方向、事件计数（已占用 `F A G T N B C M L D E W V K S P Q R U X Y`；**`H I J O Z` 空闲**）；
2. **CSI→像素 结果通道**：指尖/事件坐标（复用 CTRL_SYNC 上行按模式复用，或加第二个 26 位字）——M3 联调必需；
3. **M1 遗留**：① 示教那一拍补一条 DBG 行（`A=`/`G=` 本来就有，只缺触发）；② "形态学 3×3 不做"的确认；③（老需求）A 段参数通道 `0x40~0x7F`、`ae_set` 默认曝光偏低。
