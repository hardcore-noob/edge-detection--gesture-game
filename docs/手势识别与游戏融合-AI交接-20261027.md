## 3. 当前识别链路

```text
MIPI 摄像头
  → ISP/AWB/肤色判据
  → 背景块运动门
  → recog_top
      → 捕获态：肤色 ∩ 运动块
      → hand_band：逐行 span/密度/形状门 + 水平窗
      → 质心/ROI/锁定状态机
      → M2 指尖
      → 动态手势状态机
  → 40 位手势事件字 + 指尖坐标
  → VIDEO_TAP（CSI 域 → 像素域整包捕获）
  → game_gesture
  → 扫掠带 / game_fruit / game_render
```

关键源码：

| 路径 | 职责 | 修改前必看 |
| --- | --- | --- |
| `user_source/hdl_source/isp/recog_top.v` | 肤色/运动权重、质心、锁定、行带接入、粘指、手势事件 | 大量状态机共用 `S_band_*`/`S_tip_*`；先读附近注释 |
| `user_source/hdl_source/isp/hand_band.v` | 行级手部候选带、形状门、水平窗、运动证据 | 当前只输出一条连续候选带，绝对面积/宽高门会影响远手 |
| `user_source/hdl_source/design_top_wrapper.v` | `VIDEO_TAP`、跨域整包捕获、游戏输入接线 | 不要破坏帧锁存和握手 |
| `user_source/hdl_source/game/game_gesture.v` | 40 位事件字解码成单拍斩击请求 | `seq` 变化 + `dir∈{1,2,3}` 是事件语义 |
| `user_source/hdl_source/game/game_fruit.v` | 扫掠击中和水果状态 | 识别验收前不改计分/切割语义 |
| `user_source/hdl_source/game/game_param.v` | `W 85` 输入源、`W 95` 扫掠参数 | 默认输入源是手势 |
| `user_source/hdl_source/game/game_top.v` | 游戏层接线 | 保持 0 拍像素域边界 |

冻结接口以 README §12 为准。40 位事件字、`VIDEO_TAP` 字段、`0x95` 扫掠带语义、
游戏计分口径都不要在识别未验收时单独改写。

## 4. 已经完成并验证的部分

- 720P MIPI → ISP → HDMI 主链路、RAW/EDGE、OSD、按键和 UART 已可用。
- “手停约 1 秒后掩码消失、准星冻结后乱跳、斩击发不出”的锁定振荡已修复：
  锁定后保持肤色权重，质心使用 `MIN_WSUM_HOLD` 滞回。
- `hand_band` 已成为质心、ROI、M2 顶带和手势 `y_min` 的权威手框来源。
- P0-04a/b 已加入：捕获态块级运动证据、锁定置信度、低置信度释放/重播种和
  “仍像手”的短时保持。
- 粘指已加入：指尖使用从手框顶带向下的轮廓选择逻辑，减少手指边缘缺口造成的 x 抖动。
  但这版仍需要上板确认“刀锋是否真正稳定在指尖”。
- 捕获态运动权重阶段一已加入：已确认运动的 16×16 块内，肤色像素使用自身皮肤分；
  块外权重为 0。它改善远手播种，但没有放宽锁定期和行带的绝对阈值。
- 手势事件和切水果扫掠带已经打通；左右挥相对稳定，下劈仍是最弱方向。

## 5. 当前未完成问题

详细信息以
[`手势识别待修复问题-20261023.md`](手势识别待修复问题-20261023.md) 为准。
这里的顺序是当前建议，不要因为旧清单里写着“已实现”就认为已经上板验收。

### 第一优先：先验收现有基线

1. **P0-02 粘指/刀锋位置**：确认刀锋是否稳定在指尖，而不是手部上缘或脸部左上。
2. **P0-01 行带隔离**：场景 C 下框是否只包手，不把脸、手臂、同排木板合并进来。
3. **P0-04 背景误检**：静止黄板是否仍跟着手出现；锁错后能否释放并重新捕获手。
4. **P0-03 下劈**：每方向挥 20 次，下劈目前仍是主要失败点。

### 第二优先：识别鲁棒性

5. **P1-05/P1-07 诊断可信度**：调试图与 `recog_algo` 耦合，`DBG` 的 P/Q/R 仍可能
   整包捕获失败。算法优化前先建立可信观测，否则无法区分“种子、行带、指尖、Σw、
   锁定状态机”哪一层先失败。
6. **P0-05 光照**：白光/自然光下掩码闪断；黄光下背景黄板同时过门。AWB 是逐帧全局，
   缺少时间平滑。
7. **P1-02 误锁恢复**：静态木板/脸被误锁后，旁边有手运动也未必释放。
8. **P1-03/P1-11 远距离**：远手在 `Σw`、行 span、整带面积、宽高门、连续命中条件中
   可能逐级失效；不要把问题直接归因于肤色。
9. **P1-10 资源**：当前 86.87%，距离 90% 红线只剩约 664 slices。每次 RTL 改动都要
   重新看 LUT6/slices/WNS，优先用状态复用、位切片和已有 ERAM，避免新增大型并行比较器。

### 第三优先：游戏融合

10. 修复刀锋坐标与画面指尖镜像/偏置；
11. 明确左右挥、下劈到扫掠带方向/位置/提示帧数的映射；
12. 处理事件重复触发、漏触发和跨域延迟；
13. 最后再做计分、刀光、粒子和资源裁剪。

## 6. 推荐执行顺序

### 阶段 A：当前 bit 识别基线

先不要改代码。按以下步骤上板：

```text
W 08 0000
W 08 0001
W 08 000B
W 08 000A
W 08 0005
```

分别记录：

- 静止手 10 s 是否丢锁；
- 左/右/下各挥 20 次，成功次数；
- 60 s 空闲误触发次数；
- 场景 A（只有手）和场景 C（手、脸、手臂、黄色桌面）的行带框；
- 白光、自然光、黄光三种光照下的掩码连续性和背景误检；
- 远距离首次锁定、近处锁定后拉远能否保持。

**完成条件**：知道当前版最先失败的是哪一项，并有次数/帧数，而不是只有主观描述。
采集视图切换前先 `W 08 0000`，避免 `W 08 0001` 同值写入不重新提交。

### 阶段 B：一次只修一个问题

建议从阶段 A 的第一个失败点选一项，优先级如下：

1. 若下劈失败，先查 `S_band_ymin`、`S_tip_y` 和 M2 手势阈值；固定手框/指尖后再调方向阈值。
2. 若场景 C 锁脸，先检查 `hand_band` 的候选选择和形状门；暂不恢复行缓存/run 填充。
3. 若背景粘连，先接可信诊断字段，再评估块内运动证据、锁定置信度和 AWB 平滑。
4. 若白光/自然光失败，先分别验证原始肤色与运动块，不要同时放宽颜色门和形状门。
5. 若远距离失败，依次查 `Σw`、行带面积/宽高、`S_band_valid`、`S_tip_ok`、`S_miss_cnt`。

**完成条件**：只改一处，构建 0 违例且 slices ≤90%，上板确认目标指标改善且回归项不退化。

### 阶段 C：识别验收通过后接游戏

最小验收线建议保持：

- 手静止 10 s 不丢锁；
- 左右挥、下劈每方向 ≥18/20；
- 60 s 空闲误触发 ≤1；
- 场景 C 不锁脸，行带框贴手；
- 游戏中的刀锋/扫掠带方向与用户动作一致。

达到这些条件后，才修改 `game_gesture`、`game_fruit` 或计分语义。

## 7. 上板调试与判读

串口：`115200-8-N-1`，CR/LF。测试识别时不要按 KEY4，因为短按会重置
`recog_algo`。进入游戏模式时才按 KEY4。

常用命令：

```text
W 08 0000      # 先清零，强制下一次模式提交
W 08 0001      # 交付档：掩码 + 黄十字/刀锋
W 08 0005      # 只看原始肤色；会切到档 5，运动门关
W 08 000A      # 档 10：正常手势门限 + 三色提示条
W 08 000B      # 档 11：松手势门限 + 三色提示条
W 08 0006      # 行带/融合诊断；短时目视使用
```

提示条：

- 左侧红条：左挥；
- 右侧绿条：右挥；
- 底部蓝条：下劈；
- 顶部浅蓝/青条：有动作但方向不明确。

`K = {4'h0, recog_algo, game_mode, display_mode}`。例如 `K=0100` 表示
`recog_algo=1, game_mode=0, display_mode=RAW`。

当前 `DBG` 的 P/Q/R 仍可能不可信；在修复整包捕获前，验收以画面、提示条和
游戏 `hit_cnt` 为主，不要用单行 `P/Q/R` 直接下结论。

## 9. 不要重复的失败路线

- W09 行缓存/run 状态机/块行填充效果不合格，已经从当前分支移除。
  相关代码只存在于备份分支和 tag，不要从那里恢复后再直接接入主识别链路。
- 当前 `hand_band` 仍是一条候选带；之前尝试用 320 bit 行缓存和完整 run 扫描，
  导致 59 MHz 时序/边界问题，最终放弃。若未来重新考虑，必须先做单模块时序评估。
- 不要只凭 `W 08 0005` 的肤色可见性判断锁定链路正常；肤色、运动播种、行带形状门、
  `S_cent_valid`、`S_tip_ok`、`S_hit` 和锁定状态机是不同层。
- 不要在未确认根因时同时放宽肤色窗、运动阈值和形状门，否则背景误检会同时增加。
- `official_example/` 是工作区已有资料，保持不动、不提交。
