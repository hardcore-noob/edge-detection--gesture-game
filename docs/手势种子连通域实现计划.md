# 手势种子连通域实现计划

> 制定日期：2026-10-29  
> 目标分支：`feat/seed-connected-component`  
> 适用范围：CSI 域手部识别支路  
> 第一版目标：以二维种子连通区域替代行带 bbox 作为手部对象范围，并进入交付主路径

---

## 1. 目标

当前手部识别以 `hand_band` 的一维行带为对象范围。水平窗、行有效门、窄行拆带
和 band bbox 会影响最终掩码、ROI、指尖搜索范围以及后续刀锋位置。

本计划新增一条**带种子的降采样二维连通区域**：

- 现有 `hand_band` 继续负责产生稳定的手掌候选和种子；
- 区域生长从种子出发，在完整 `80×45` 粗图上确定当前手部二维组件；
- 组件占用图进入主路径，成为手部 mask、bbox 和 ROI 的对象先验；
- 不使用 `H_WIN`、ROI 或旧 bbox 裁切生长图；
- 第一版保留现有锁定状态机和 M2 指尖算法，不修改其判定条件；
- 组件结果相对图像滞后一帧，约 16.7 ms；
- 丢失跟踪锁定时显示 mask 立即消失。

这不是全分辨率连通域标号，也不是识别画面里的所有组件。第一版只求从固定种子
生长出**一个目标组件**。

## 2. 当前资源基线

以 2026-10-31 最新 PnR 报告为准：

| 资源 | 当前用量 | 占比 |
|---|---:|---:|
| slices | 17785 / 21216 | 83.83% |
| LUT6 | 16249 / 21216 | 76.59% |
| 触发器 | 15857 / 42432 | 37.37% |
| ERAM | 78 / 108 | 72.22% |
| DSP | 8 / 40 | 20.00% |
| feedthrough | 6357 | — |
| final Setup WNS | +658 ps | 0 违例 |
| final Hold WNS | +20 ps | 0 违例 |

当前门禁：

- slices `< 95%`，即最多约 20155 slices；
- final Setup `>= +200 ps`；
- Hold 无违例；
- 0 ERROR；
- 一次 PnR 成功并生成 bit。

到 slices 门禁尚有约 2400 slices 余量。本计划预计新增 650~1100 slices 和
10~14 块 ERAM，资源上可行；必须通过实际综合确认。

## 3. 已确定的设计决策

| 主题 | 决策 |
|---|---|
| 版本范围 | 第一版直接进入主路径，同时保留编译期旁路用于回退和 A/B |
| 对象目标 | 只生长当前种子所属的一个组件 |
| 降采样 | `1280×720 -> 80×45`，每格 `16×16` 像素 |
| 生长单位 | 粗格子，不是一次填充完整的 16×16 像素块 |
| 邻接 | 首版使用 4 邻域 |
| 肤色来源 | 全分辨率 `S_m_pick_v`，即 ROI、hand band 和显示 bbox 之前的去噪肤色流 |
| 核心占用门 | 每格 `S_m_pick_v` 像素数 `>= 24 / 256` |
| 阈值替代 | 若上板背景误入，编译期改为 32；不做在线切换 |
| 运动用途 | 只用于播种和重捕获，不作为锁定后的持续硬门 |
| 边缘用途 | 阻挡格间跨接，不用于填充格内部 |
| 边缘门限 | 独立固定 `E_BARRIER`，不受显示边缘门限影响 |
| barrier 判据 | 共享边界 16 个采样点中至少 8 点超过 `E_BARRIER` |
| barrier 时序 | 首版单帧生效，不做两帧确认 |
| 组件 bbox | 组件有效时成为权威 bbox；组件无效时回退 `hand_band` |
| bbox 平滑 | 沿用当前 1/2 平滑和 48 px 跳变规则 |
| 组件统计 | 加入格子时同步累计面积、bbox、中心和坐标和；不做独立的第二轮统计 |
| 孔洞修补 | 提供单格局部补洞 pass，默认关闭，只用于验证孔洞造成的缺口 |
| 种子查找 | 中心 5×5 粗格内最近占用格，再回退当前运动区域 |
| 全分辨率 mask | 当前帧 `S_m_pick_v` 与组件及 1 格 halo 相交 |
| 强边缘轮廓精修 | 不进入第一版，留到后续增量 |
| 跟踪锁定与指尖 | 现有 `S_hit/S_locked`、M2 扫描和粘指逻辑保持不变 |
| 一帧延迟 | 接受；当前帧生成特征图，下一帧消费组件结果 |
| 丢失锁定 | `track_locked=0` 时 mask 立即清零 |
| 组件短时失效 | 跟踪仍锁定时回退现有 hand band mask；连续 3 帧失败后标记组件无效 |

## 4. 第一版不做的事情

- 不做 1280×720 全分辨率 visited/label 图。
- 不缓存全分辨率 mask。
- 不识别画面中的所有连通组件并给每个组件编号。
- 不修改 `S_hit`、`S_locked` 或指尖扫描/粘指判定。
- 不做基于强边缘的全分辨率轮廓精修。
- 不删除 `hand_band` 的 `H_WIN` 或 `NARROW_ROWS`。
- 不让生长图受 `H_WIN`、ROI 或旧 bbox 裁切。

## 5. 总体数据流

```text
当前帧全分辨率输入
  ├─ S_m_pick_v ───────────────> 16×16 肤色占用统计 ──> F_skin[80×45]
  ├─ S_motion_mask ───────────> 现有运动地图（仅播种/重捕获）
  └─ Sobel 原始梯度 ──────────> E_BARRIER ──> 格边界边缘计数 ──> E_boundary[80×45]

hand_band（H_WIN + NARROW_ROWS）
  -> 稳定手掌 bbox/中心
  -> 主种子

F_skin + E_boundary + 种子 + 上一组件中心
  -> 80×45 4 邻域区域生长
  -> C_core[80×45] + 同步累计组件属性
  -> 可选单格孔洞修补
  -> 1 格膨胀
  -> C_halo[80×45]
  -> 组件 bbox、面积、中心、valid

下一帧主路径
  ├─ display_mask = track_locked && S_m_pick_v && C_halo
  ├─ ROI / M2 bbox = component_bbox（无效时回退 hand_band bbox）
  └─ 现有 M2 指尖逻辑保持不变
```

## 6. 帧时序与延迟

当前视频为 1280×720@60，单帧周期为：

```text
1 / 60 = 16.67 ms
```

帧时序：

```text
Frame N：
  在线累计 F_skin / E_boundary

Frame N 帧末或消隐期：
  选择种子
  在粗图上执行区域生长
  加入组件格子时同步累计组件统计
  可选执行一次单格孔洞修补
  完成 core/halo 图

Frame N+1：
  使用 Frame N 的组件图做对象门控
  同时累计 Frame N+1 的新特征图
```

组件身份相对当前帧约滞后一帧，但最终显示的边界像素仍来自当前帧
`S_m_pick_v`，不是上一帧的肤色像素。

特征图和组件图使用双缓冲，避免下一帧写入与当前生长读取冲突。若生长在下一帧
开始前仍未完成，本帧组件判为失败并走回退，不阻塞视频主通路。

## 7. 数据存储

### 7.1 `F_skin`：肤色占用图

- 尺寸：`80×45`，3600 格；
- 每格保存 `S_m_pick_v` 的像素数，8 bit；
- 首版不保存每格 RGB 或二值像素；
- `F_skin(x,y) >= 24` 表示该格可参与生长；
- 32 是编译期替代阈值，不作为运行时寄存器。

建议使用双缓冲，共约 4 块 ERAM。

### 7.2 `E_boundary`：共享边界边缘计数

- 每个粗格保存右边界和底边界的强边缘计数；
- 每个方向 4 bit，饱和到 15；
- 左边界和上边界由左邻格、上邻格的数据复用；
- 每格共 8 bit；
- 建议双缓冲，共约 4 块 ERAM。

边缘计数不能直接复用显示门限。计划在 `edge_detect_96` 的同一条 Sobel 梯度
通路上增加固定门限的 `E_BARRIER` 输出：

```text
display_edge = mag >= I_edge_th
barrier_edge = mag >= E_BARRIER
```

不新增第二套 Sobel 或行缓存。

边缘图相对 RAW 左移 1 像素并晚 2 拍。边缘统计使用自己的 `tuser/tvalid` 和
坐标计数，在格边界附近允许 ±1 px 对齐误差，不要求与 RAW 像素逐拍完全同相。

### 7.3 组件图

生长至少需要：

- 当前可达图；
- 下一轮可达图；
- 上一帧输出组件图。

输出组件图每格保存：

```text
bit0 = core
bit1 = halo（core 向外扩 1 格）
```

`core` 用于面积、bbox 和对象成员统计；`halo` 只用于当前帧显示精修。

组件图建议使用 ERAM 双缓冲，约 2~4 块。总 ERAM 预算控制在 10~14 块，当前剩余
32 块，空间足够。

所有大数组必须显式使用 `eram_spram`，禁止被综合成分布式 RAM。

## 8. 种子选择

优先级固定为：

1. 上一帧组件有效时，选择上一组件与当前 hand band 重叠、且离预测位置最近的占用格；
2. 当前 `hand_band` bbox 中心；
3. 当前运动质心；
4. 若仍无可用种子，则本帧组件失败。

当首选坐标落在低占用格时，在中心周围 `5×5` 粗格内按 Manhattan 距离由近到远
搜索第一个 `F_skin >= CELL_MIN_SKIN` 的格子。

若 5×5 内没有占用格，则在当前运动区域内寻找离首选坐标最近的占用格。

种子格必须出现在最终生长组件中，否则该帧组件无效。

## 9. 区域生长算法

### 9.1 前置条件

B 格能从 A 格加入组件，需要同时满足：

1. A 已在当前组件中；
2. B 与 A 四邻接；
3. B 在 `80×45` 图像范围内；
4. `F_skin(B) >= CELL_MIN_SKIN`；
5. B 尚未访问；
6. A-B 共享边界不是 barrier。

门槛顺序固定：先判 B 的肤色占用，再判边缘 barrier。肤色占用不足时直接拒绝，
不读取边缘阻挡结果。

### 9.2 邻接和 barrier

首版只使用四邻域，避免从粗格斜角钻过狭窄背景缝隙。

共享边界定义：

- 左右相邻格检查竖直边界；
- 上下相邻格检查水平边界；
- 在边界所在列或行及相邻 ±1 px 范围内统计 `E_BARRIER`；
- 16 个采样点中至少 8 点满足 `E_BARRIER` 时形成 barrier。

边缘阻挡是负向门，不是正向肤色判据。格内部是否属于手仍由 `S_m_pick_v`
占用决定。

指缝中露出背景时，目标格通常先因 occupation 不足被拒绝；边缘 barrier 是第二道
保护。并拢手指与手掌连通时，生长可以通过除指缝外的其他邻接路径进入手指。

### 9.3 生长状态机

建议使用多周期 wavefront 扫描，不在每拍并行检查所有邻居：

```text
IDLE
  -> CLEAR
  -> SEED
  -> GROW pass
  -> GROW pass
  -> ... until no new cells
  -> OPTIONAL_FILL_HOLES
  -> DILATE_HALO
  -> COMMIT_SWAP
```

每遍扫描 3600 格。手部组件在粗图中的直径通常只有几十格，因此需要多遍传播，
但全部发生在帧间隙，按 59 MHz 估算仍在毫秒级。

每次把一个格子加入 `C_core` 时，同步更新：

- 组件粗格 bbox；
- 组件肤色面积；
- 组件粗格数量；
- Σx / Σy；
- 组件中心所需累加量。

因此进入 `COMMIT_SWAP` 前不需要再次遍历 `C_core` 计算属性。

若状态机在下一帧开始前没有完成，则丢弃未完成组件并走回退。

### 9.4 可选单格孔洞修补

在 `C_core` 生长完成后，可选择一个编译期关闭的 `FILL_HOLES` pass。
它只处理单个未占用格，不运行通用形态学，也不扩展组件外边界。

首版建议采用便宜的单方向局部关系：

```text
fill(x,y) = top_core && (left_core || right_core)
```

该规则只补一个粗格大小的内部凹陷，成本近似一次粗图扫描。

限制：

- 默认 `FILL_HOLES=0`；
- 只能修补 `C_core` 中的单格孔洞；
- 不跨越 barrier；
- 不把填充结果用于 seed 重定位；
- 是否把修补格计入面积/bbox，由同一开关决定，避免调试图和统计口径分叉。

如果上板没有明显的单格孔洞，不启用该逻辑，以节省资源和验证成本。

## 10. 组件统计与有效性

### 10.1 统计量

组件属性在生长过程中同步累计，不在 `C_core` 完成后做第二轮扫描：

- 组件粗格 bbox；
- 组件肤色像素面积：累加组件格的 `F_skin`；
- 组件粗格数量；
- 组件中心；
- 组件内运动格数量，仅用于诊断；不参与第一版组件有效性。

### 10.2 bbox 坐标

组件 bbox 从格子边界换取：

```text
x_min = 16 * min_cell_x
x_max = 16 * (max_cell_x + 1) - 1
y_min = 16 * min_cell_y
y_max = 16 * (max_cell_y + 1) - 1
```

组件 bbox 与现有 bbox 使用相同的 1/2 平滑和 `SNAP_DELTA=48` 跳变规则。
组件占用图本身不因 bbox 平滑而被裁切。

### 10.3 有效条件

组件必须满足：

- 种子格属于组件；
- 组件累计肤色面积 `>= 2000 px`；
- bbox 宽 `>= 60 px`；
- bbox 高 `>= 60 px`；
- 高不超过宽的 4 倍；
- 宽不超过高的 5 倍；
- 组件 bbox 与当前预测中心的距离在 `SEARCH_R=256` 范围内。

组件首次满足条件后立即生效。连续 3 帧生长失败后，`component_valid=0`。

## 11. 主路径接入

### 11.1 对象 bbox

组件有效时：

```text
object_bbox = smoothed_component_bbox
```

组件无效时：

```text
object_bbox = existing_hand_band_bbox
```

原有 `S_hit`、`S_locked`、M2 扫描、粘指和刀锋接口不修改。它们接收的对象 bbox
来源由上述 mux 决定。

### 11.2 全分辨率 mask

组件有效且跟踪锁定时：

```text
display_mask = S_m_pick_v & C_halo
```

其中：

- `S_m_pick_v` 位于 ROI 和 band bbox 门控之前；
- `C_halo` 是组件向外扩 1 格的显示许可图；
- 不对 display mask 再套 `H_WIN`、ROI 或旧 bbox；
- `C_halo` 只用于显示和轮廓恢复，不参与组件面积、bbox 或有效性。

### 11.3 回退

```text
track_locked = 0
  -> display mask 立即清零

track_locked = 1 && growth_ok = 1
  -> 组件 bbox + 组件 mask

track_locked = 1 && growth 连续失败 1~2 帧
  -> 回退现有 hand_band bbox/mask

track_locked = 1 && growth 连续失败 >= 3 帧
  -> component_valid = 0，继续使用现有 hand_band 路径直到跟踪失锁
```

锁定状态拥有最高清屏权。组件短时失败不能把已经锁定的手直接清空；真正失锁时
不能继续显示旧组件。

### 11.4 后续边缘精修接口预留

后续可以增加独立 `edge_refine` 阶段：

- 只在 `C_core/C_halo` 边界附近运行；
- 使用当前帧全分辨率肤色和 `E_BARRIER`；
- 不允许改变组件身份；
- 不进入第一版。

## 12. 调试与观测

交付构建默认 `COMP_DBG=0`。调试构建通过编译期 `COMP_DBG=1` 增加：

1. `F_skin` 阈值占用视图；
2. `E_boundary` barrier 视图；
3. `C_core` 组件视图；
4. `C_halo` 显示许可视图；
5. 最终 `display_mask` 与组件 bbox；
6. 被 barrier 拒绝的边界；
7. 回退状态和连续失败计数。

建议暴露以下帧锁存观测：

- `component_valid`
- `growth_ok`
- 当前种子格坐标
- 组件格数
- 组件肤色面积
- 组件 bbox
- 连续失败帧数
- barrier 拒绝次数
- 生长完成所需 pass 数

调试字段优先使用编译期专用 bit，不挤占交付关键路径。

## 13. 资源预算

估算按完整粗图、双缓冲和边缘阻挡实现：

| 项目 | 预计新增 |
|---|---:|
| slices | 650~1100 |
| logic LUT | 700~1200 |
| FF | 300~600 |
| ERAM | 10~14 |
| DSP | 0 |
| 预计最终 slices | 18205~18655（85.8%~87.9%） |
| 预计最终 ERAM | 86~90 / 108 |

以上为设计预算，误差按 ±30% 理解。关键风险不是容量，而是：

- ERAM 端口争用；
- 粗图地址 mux；
- 状态机控制路径；
- feedthrough 和布局拥塞。

每次构建必须同时记录 slices、LUT6、FF、ERAM、DSP、feedthrough、Setup/Hold、
是否一次 PnR 和 bit 路径。

## 14. 实施阶段

### Phase 0：分支与基线

1. 从稳定的当前 main 新建 `feat/seed-connected-component`。
2. 保留 `tmp/` 中现有可用 bit 作为回归对照。
3. 确认当前综合/PnR 基线可以复现。
4. 增加 `COMP_EN` 编译期旁路，默认交付值为 1，回退构建可置 0。

### Phase 1：粗图特征与独立边缘位

1. 新增 `16×16` 格累计器，生成 `F_skin`。
2. 在现有 Sobel 输出上增加固定高门限 `E_BARRIER`。
3. 统计每格右边界和底边界的强边缘数。
4. 完成 `F_skin`/`E_boundary` ERAM 双缓冲。
5. 添加编译期调试视图。
6. 只验证统计通路，不接主路径。
7. 构建并提交一个原子 commit。

### Phase 2：种子区域生长与组件统计

1. 实现种子优先级和 5×5 回退搜索。
2. 实现四邻域 wavefront 生长。
3. 实现 occupancy → barrier 的固定检查顺序。
4. 加入格子时同步累计面积、bbox、中心和坐标和。
5. 生成 `C_core`，再做 1 格 halo。
6. 实现组件有效性和 3 帧失败滞回。
7. 增加 `FILL_HOLES` 编译期开关和单格补洞 pass，默认关闭。
8. 增加未完成状态机超时/丢弃路径。
9. 构建后先用调试视图确认组件正确，再接主路径。
10. 构建并提交一个原子 commit。

### Phase 3：主路径接入

1. 组件有效时，让组件 bbox 替换 `hand_band` bbox。
2. 组件无效时回退 `hand_band` bbox。
3. 组件有效时，使用 `S_m_pick_v & C_halo` 作为显示 mask。
4. `track_locked=0` 时立即清零 mask。
5. 保持 `S_hit/S_locked` 和 M2 指尖逻辑不变。
6. 检查所有 `VIDEO_TAP`、ROI、M2 和游戏刀锋数据相位。
7. 完整构建并提交一个原子 commit。

### Phase 4：上板调参

1. 使用保存的旧 bit 和新 bit 做同场景对照。
2. 对比 `CELL_MIN_SKIN=24`；必要时重新构建 32 版本。
3. 对比 barrier 开关。
4. 对比 `FILL_HOLES` 开关，确认单格补洞是否带来真实收益。
5. 如手掌纹误挡明显，再评估提高边界覆盖率门限或增加两帧确认。
6. 记录最终参数、资源和上板结论。

## 15. 上板验收

### 15.1 基础功能

- RAW/EDGE、基础 OSD、UART 和游戏层不回归；
- `F/A/G/T`、`D/E` 正常；
- `U=0384`；
- 无新增静默丢帧。

### 15.2 组件正确性

- 静止张开手 10 s，组件稳定且不上下跳；
- 握拳后组件和 mask 不消失；
- 五指张开时 halo 能恢复粗格切掉的指尖；
- 手快速左右移动时组件能持续跟随；
- 手与脸、手臂、黄色木板同屏时，barrier 不把整只手切碎；
- 黄板/桌面不被大面积纳入组件。

### 15.3 主路径与游戏

- 组件有效时 bbox 与最终 mask 一致；
- 组件短时失败时 hand band 能回退；
- 真正失锁时 mask 立即消失；
- 切水果轨迹和命中率不明显退化；
- 左右挥、下劈和快速单手挥的原有操作不回归。

### 15.4 构建门禁

- slices `< 95%`；
- final Setup `>= +200 ps`；
- Hold 0 违例；
- 0 ERROR；
- 一次 PnR 成功；
- bitgen 成功；
- `COMP_EN=0` 回退构建行为与旧版本一致。

## 16. 风险与回退

| 风险 | 处理 |
|---|---|
| 手与皮肤色背景真实连通 | 优先调高 `E_BARRIER` 和共享边界覆盖率 |
| 手掌纹/指缝误挡 | 使用高门限；必要时两帧确认或关闭 barrier |
| 24 阈值背景误入 | 编译期改用 32 |
| 白光下手指占用不足 | 先检查 halo 和阈值；后续再加弱肤色补洞 |
| 一帧组件滞后 | 保持当前像素边界，使用轨迹历史和 bbox 平滑 |
| ERAM 端口冲突 | 在帧间隙分时处理，禁止组合跨 RAM |
| PnR 拥塞 | `COMP_EN=0` 回退，再按面积报告裁剪 |
| 主路径替换引入游戏回归 | 保留旧 bit，逐项比较 mask、bbox、刀锋和命中 |

立即回退方式：

```text
COMP_EN = 0
```

回退路径必须恢复到当前 `hand_band` bbox、`S_mask_disp`、ROI 和 M2 指尖行为。
