# FPGA 手势操控游戏 — 实现路线规划

> 平台：HX1P35A 开发板（安路 PH1P35MDG324）
> 基线：基础要求已全部完成（MIPI 采集 → ISP → 边缘检测 → DDR2 → HDMI + OSD Logo）
> 资源基线（2026-09-13 于本 worktree 重跑复现，main @ 93afd2b）：slices **13214 / 62.28%**、LUT6 10809（到 85% 只剩约 +3950 LUT6）、ERAM **70/108（余 38 块）**、DFF 14256 / 33.60%、DSP 8/40、feedthrough 6767、final Setup WNS **+820 ps**（0 违例）
> 版本：v1.3，2026-09-13（基线更新为 13214/62.28% 并写入预算门禁；补跨时钟域接口契约与判定帧对齐；里程碑验收加时序指标；移除按键输入源与卡通化；补 DBG 可观测量与赛题覆盖）

## 0. 总体架构

```
SC500CS ─MIPI→ CSI解包 → ISP → [识别支路] → RAW/EDGE MUX → DDR2帧缓存 → [游戏/OSD渲染层] → HDMI TX
                                          │                                   ▲
                                          └─── 每帧少量结果（坐标 / 判定）──────┘

  [识别支路：CSI 域 ~59MHz，与像素域异步]        [游戏/OSD 渲染层：HDMI 像素域 75MHz]
   边缘检测(已有)          人体/手势跟踪链路(新增)      游戏引擎(vsync 节拍)
                           ├─ 肤色YCbCr掩码 ──┐         ├─ Pong
                           ├─ 运动掩码(背景差分)├─AND→融合掩码  ├─ 打砖块/贪吃蛇
                           ├─ 形态学去噪      ──┘         │   ├─ 切水果(精灵+粒子)
                           ├─ ROI门控包围盒/质心统计(相机域)   │   └─ 人体躲避框(掩膜碰撞)
                           ├─ 指尖提取(复用边缘图)         ├─→ 手部质心/指尖
                           └─ 轨迹状态机                   └─→ 形状窗口判定(相机域)
    取点：识别支路接在 isp_top 内部、RAW/EDGE MUX 之前（EDGE 模式下也必须仍有颜色）
    主线输入源(可插拔)：手势质心·指尖 / 人物掩膜统计 / 乒乓开关(菜单与示教)
    可选拓展输入：IMU体感手柄(UART) —— 仅接入输入抽象层，不改游戏引擎
    兜底方案：荧光色指套（一键示教切换为色块跟踪，裸手失效时的 Plan B）
```

**核心原则**
1. 游戏渲染走"程序化渲染"（逐像素判属），挂在 hdmi_mixer 后级，不用 framebuffer
2. 所有模式切换在场消隐期发生，防画面撕裂
3. 游戏/OSD 层可整体旁路——基础视频链路任何时候独立稳定
4. 每完成一个里程碑必须编译实测，门禁见 §6：slices ≤85%（90% 红线）+ final Setup WNS ≥ +300 ps + feedthrough 不失控 + 一次布局布线成功
5. 输入抽象层从第一天就按"多源可插拔"设计——手柄日后作为纯增量接入，主线不为其等待
6. **融合掩码是一鱼两吃的核心资产**：降采样后供手部定位，全分辨率供躲避框碰撞检测（两个消费者都在 CSI 域）
7. **跨时钟域只交换每帧少量结果**：识别在 CSI 域、渲染在 HDMI 像素域（SDC 里两组时钟已设为异步），不传全帧掩膜；形状几何（像素域→CSI 域）与判定结果（CSI 域→像素域）各一条通路，并定义帧对齐策略

## 2. 三人分工

| | 成员 A：视觉算法 | 成员 B：游戏引擎 | 成员 C：系统与验证 |
|---|---|---|---|
| 技能画像 | 视频流水线、图像算法 | Verilog 状态机、时序逻辑 | 工程化、测试、动手能力强 |
| 第 1 周 | M0 重构 → M1 融合掩码跟踪 | 接口约定 → 游戏骨架（假输入）→ Pong | M0 配合（模式框架/寄存器通道/存档）→ 延迟测量模块 → 测试基础设施 |
| 第 2 周 | M2 指尖/动态手势 → 支持 Pong/躲避框接入 | M3 收尾（手势接入 Pong）→ M4a 切水果 | M4b 砖块/贪吃蛇 → M4c 人体躲避框（M1 掩码就绪后开工，与 B 并行） |
| 第 3 周 | 边缘风格化收尾 + 配合整合 | 切水果收尾 + 手感调优 | M5 整合牵头 → M6 固化/彩排/报告素材 |
| 弹性职责 | 跟踪链路的现场稳定性 | 游戏手感与演示效果 | 全队的备胎与保险丝：谁崩顶谁；X1 手柄的主人 |

**并行前提——第一天冻结五份接口契约**（三人一起，1~2 小时）：
1. 模式寄存器表（模式 ID + 场消隐期切换协议）
2. **跨域接口契约（两域异步，不做全帧总线）**：①`ctrl_x / ctrl_y / valid` 每帧锁存（CSI 域 → 像素域）；②躲避框形状几何（像素域 → CSI 域，每帧一次）；③判定结果/填充率（CSI 域 → 像素域，每帧一次）；④帧对齐：判定帧定格 ≥3 帧，容忍 DDR 帧存带来的 ±1 帧错位
3. 掩码统计器接口（A 的 M0 产出，他人不依赖内部）
4. OSD 层级优先级表：**OSD 文字层（安路 Logo / 状态字 / 菜单）> 游戏层 > 摄像头背景**——基础要求 4 的 Logo 与算法状态字在任何模式下都必须可见，游戏层不能盖住它们
5. 资源配额分账（≤85% 封顶，合计 3900 LUT6）：A ≈1400（M1+M2），B ≈1200（M3+M4a），C ≈1200（M0+M4b+M4c+M5），机动 100，谁超支谁自己找回来

**协作纪律**：每人一个功能分支，主线永远可固化；每两天一次短会同步接口/资源/进度；联合调试成对半天进行（M1→Pong、M1→躲避框、引擎→砖块、最终整合），不搞大爆炸式整合。

## 3. 分阶段详案

### M0 模块重构与基础设施（2 天，A+C）

**目标：为后续所有功能铺路，不加任何新功能**

- [ ] 把 `edge_detect` 中的 **3×3 行缓存窗口生成器拆成独立模块**（行缓存 + 窗口寄存器阵列），Sobel 算子只消费窗口
  - 后续形态学与掩码去噪复用它（卡通化已从规划移除）
- [ ] 实现通用 **二值掩码统计器**（包围盒 min/max、像素计数、质心累加），输入掩码可 mux 选源（边缘/肤色/融合/帧差）
- [ ] 建立**模式控制框架**：乒乓开关电平采样（含 20ms 消抖）+ 模式寄存器 + 场同步切换逻辑（vsync 边沿更新模式，杜绝撕裂）【C】
- [ ] 建立寄存器/参数在线调整通道（乒乓开关 + UART 接收）：阈值、灵敏度、物理参数可现场调，不重编译【C】
- [ ] **存档当前基线**（13214 / 62.28% / Setup +820 ps）作为永久回退点：保留本轮重跑生成的 bit 流 + git tag【C】
  - 2026-09-13 已在主 worktree 重跑复现（syn 14:01 / phy 14:06，`camera_to_dsi_display.bit` 1789547 B、`_compress.bit` 1478281 B）；复现前先补了 Run 目录缺的两处：`eram_spram.v` 未登记进两个 `camera_to_dsi_display.prj`（综合报 `HDL-8007 black box`）、`phy_1/settings.cfg` 里缺 `set phyWildParams {place opt_timing high}`（不加就只有 +226 ps 量级）
- [ ] **新外设引脚登记**：乒乓开关、UART 接收（手册 RXD = J1；现在只约束了 TXD = H1）、数码管、蜂鸣器加进 `pin.adc` 并查引脚冲突——M0 的在线调参、M4c 的蜂鸣器音效、M5 的数码管延迟显示都依赖它们【C】

验收：基础四项功能回归通过；编译确认资源基线且 **final Setup WNS ≥ +300 ps**；回退镜像（bit）+ git tag 可用。

### M1 融合掩码跟踪链路（4~5 天，A）

**目标：得到一张"干净的人/手掩膜"——这是所有交互功能的地基**

肤色检测单用不靠谱（类肤色背景、光照漂移、脸手干扰），采用**肤色 ∩ 运动 双掩码融合**架构：

- [ ] RGB→YCbCr 转换（3×3 常系数矩阵，**乘法用空闲 DSP**）
- [ ] 肤色阈值掩码（Cb/Cr 双区间判定），阈值寄存器可在线调
- [ ] **运动掩码**：背景帧差分 + 阈值
  - 背景帧：降采样灰度图存 ERAM（128×75×8bit ≈ 75Kbit；块数按"位宽×深度"几何核算后确认，别直接按 bit 数 ÷ 20Kb 估），绕开 DDR2 带宽
  - 背景更新：乒乓开关手动采样（演示前拨一下，可控性最强）；可选每帧 1/16 缓慢自适应
- [ ] 双掩码按位与 → 融合掩码：肤色背景"是肤色但不动"被杀，衣物摆动"在动但非肤色"被杀
- [ ] 形态学开运算去噪（复用 M0 窗口生成器）
- [ ] **ROI 跟踪门控**：锁定后只在上帧包围盒外扩窗口内统计，窗口外干扰物理隔离；掩码像素数低于阈值连续 N 帧 → 退回全帧重新搜索
- [ ] 统计器输出：包围盒 + 质心 + 掩码像素计数
- [ ] 时域滤波：质心 α-β 滤波 + 丢失保持（丢帧维持最后位置 ≤5 帧）
- [ ] OSD 十字准星 + 包围盒叠加（复用现有 OSD 通道）
- [ ] **一键示教**（双用途，乒乓开关触发）：采样手部 Cb/Cr 均值/方差更新肤色阈值；另一个档位采样背景帧
- [ ] （可选）投影直方图选峰：融合掩码存在多个独立区域时，x/y 投影选最大峰，替代昂贵的连通域标号（~200 LUT6）
- [ ] **识别结果接进 `DBG:`**（README 点名开工前必须定的事）：掩码像素数、包围盒 min/max、质心、手型状态、手势事件计数，沿用现有"相机域统计 → 帧首锁存 → 2 级同步 → 显示域 logger"模式（`M` 与 `D/E/W/V` 就是这么做的）
- [ ] 示教与运行日志同行输出 `A`/`G`（曝光/增益）与掩码统计，现场翻车也能靠日志复盘

**全身/手部双模式**：摄像头近景拍手 → 手部跟踪（游戏操控）；拉远拍全身 → 人物掩膜（躲避框）。同一套链路，只是取景和统计窗口不同。

验收：演示者穿短袖，正常室内光下准星跟手流畅；背景出现木桌/人脸不干扰；换光照一键示教 3 秒恢复；目标出画 5 帧内丢失、回画 3 帧内重新锁定。
**编译实测 #1**，记录实际增量（slices / LUT6 / ERAM / WNS），按 §6 门禁检查。
**Plan B 备案**：指尖戴荧光色指套，一键示教切换为色块跟踪——裸手方案现场失效时的兜底（不算作弊，一键示教本就支持任意颜色目标）。

### M2 指尖提取与动态手势（2~3 天，A）

**目标：从"手在哪"到"手在干什么"**

- [ ] 指尖提取：融合掩码包围盒内，用边缘图自顶向下扫描，找最上缘轮廓峰（单峰=握拳/并指，多峰=张开）
- [ ] 手型状态输出：张开 / 握拳 / 未知（滞回比较防抖）
- [ ] 轨迹状态机：左挥 / 右挥 / 下劈（质心位移 + 速度 + 加速度阈值），手势事件脉冲输出
- [ ] 指尖坐标输出（切水果的刀尖位置）

验收：挥手方向识别准确率现场实测 >90%；张合切换稳定不抖。
**编译实测 #2**。

### M3 游戏引擎框架 + Pong（3~4 天，B）

**目标：第一个可玩游戏**

- [ ] 游戏渲染层框架：层级优先级 mux（**OSD 文字层 > 游戏层 > 摄像头背景**），逐像素矩形判属函数
- [ ] 游戏逻辑时钟域：全部挂在像素时钟域，**vsync 为游戏节拍**（60Hz 固定步长）
- [ ] 输入抽象层：手势 → 归一化控制量（**预留第二源：UART 手柄，留空不接**）
- [ ] Pong：双拍 + 球（距离平方判圆，用 DSP）+ 分数（复用字模 ROM）+ 发球/得分状态机
- [ ] 游戏整体旁路开关

验收：先用假输入源（常量 / 乒乓开关注入）验证引擎可玩，M1 完成后手势接入半天联调通过；旁路开关关闭后基础链路无任何变化。
**编译实测 #3**。

### M4a 切水果（3~4 天，B）

- [ ] 水果精灵位图存 ERAM（32×32×8bit，每张 ≤1 块，先 3~4 种）
- [ ] 抛体运动（定点重力），生成器用 LFSR 伪随机
- [ ] 刀光拖尾：最近 8~16 个指尖坐标移位寄存器，逐点判距渲染
- [ ] 粒子爆开：LFSR 粒子 + 寿命计数（击中反馈的灵魂）
- [ ] 背景用边缘化摄像头画面（黑白线稿世界切彩色水果）
- [ ] 游戏选择菜单（手势挥动翻页，张开手确认）

验收：切水果 60fps 无卡顿，指尖追踪手感顺滑。
**编译实测 #4**，确认 slices ≤ 80% 且 final Setup WNS ≥ +300 ps。

### M4b 打砖块 / 贪吃蛇（2~3 天，C，第 2 周启动）

- [ ] 打砖块：瓦片 RAM 存砖块网格（~1 块 ERAM），球拍用手势
- [ ] 贪吃蛇：瓦片网格 + 挥动换方向（动态手势消费方，帮 A 验证 M2 输出）
- [ ] 基于 B 的游戏引擎框架开发，顺便充当引擎的"第二个用户"，帮 B 暴露框架问题

验收：两个游戏稳定可玩，切换无异常。

### M4c 人体躲避框 / Human Tetris 变体（2~3 天，C，M1 完成后即可开工）

**核心机制**：屏幕生成运动的镂空形状窗口 → 玩家用身体穿过/避开 → 定格瞬间做掩膜碰撞判定。

**技术本质：二值掩膜碰撞检测**——不识别"是谁/什么姿势"，只判"这个像素是不是人"与"人和框有没有重叠"。直接消费 M1 的全分辨率融合掩膜（**同一 CSI 域内**，不做跨域全帧总线），这是该项目与手部跟踪共享地基的原因。

- [ ] 形状窗口生成器：镂空矩形（外框 - 内洞），参数化（位置/大小/洞形），从屏幕顶端下落或侧面推近（缩放模拟逼近）
- [ ] 碰撞统计（在相机域、vsync 节拍）：
  - **越界计数**：人物掩膜落在"墙体区"（外框内 - 洞外）的像素数 → 超过阈值 = 撞到
  - **填充率**：人物掩膜落在"洞内"的像素占比 → 评分依据（填充越满分越高）
  - **跨域与帧对齐**：形状几何由像素域每帧写入 CSI 域，判定结果每帧读回；判定帧定格 ≥3 帧，容忍 DDR 帧存造成的 ±1 帧错位
  - **判定用哪一帧要写死**：判的是"当前相机帧"、显示的是 1~2 帧前的画面——定格足够久，这点误差就看不出来
- [ ] 游戏流程状态机：预告 → 形状逼近 → 定格（freeze 判定帧）→ 判定 → 计分 + 特效（通过=绿闪+粒子，撞到=红闪+震动音效/蜂鸣器）
- [ ] 难度递进：形状下落速度加快、洞形变小、连续组合
- [ ] OSD：分数、连击数、判定结果大字动画
- [ ] 取景要求：摄像头拉远拍全身，演示区预留 2~3 米纵深——彩排时确认场地

**为什么这个游戏性价比极高**：渲染只有矩形（零精灵）、判定只是两个计数器，总计 ~300~400 LUT6；但它是全身交互，围观效果和搞笑程度全场第一——日本综艺《人体俄罗斯方块》的综艺感就是它的演示效果。

验收：不同体型人员实测判定准确；定格判定无延迟感；连续 10 局无状态机卡死。

## 4. 可选拓展 X1：IMU 体感手柄（3~4 天，仅主线提前完成时启动）

**启动条件（三个同时满足）**：主线 M6 完成 ≥3 天余量；slices 最终 ≤ 76%；C 无其他收尾任务。

- [ ] 手柄端固件（ESP32 + MPU6050）：互补滤波解算 pitch/roll（不碰 yaw），按键，电量指示
- [ ] 数据帧协议：`0xAA55 + ID + pitch + roll + 按键位 + CRC`，50~100Hz
- [ ] 板端 ESP32：BLE 主机双连接，汇总后 UART 转发 FPGA
- [ ] FPGA UART 接收 + 帧解析 + CRC + 断链检测（超时回退手势）——**接入点是 M3 预留的第二输入源，游戏引擎零改动**（手柄自带按键，不占用板载 KEY1~KEY3）
- [ ] **有线兜底**：手柄 USB 串口直连开发板的降级演示路径
- [ ] 双人 Pong：手柄 vs 手柄 / 手柄 vs 手势

收益：双人体感对战作为加分项；扩展 3（外部控制）改由主线的手势→板载外设覆盖，不再依赖 X1。
风险隔离：整条线独立于主线，任何一步失败直接放弃，不影响已固化版本。

## 6. 工程纪律

1. 每个里程碑结束：编译实测（slices / LUT6 / ERAM / DSP + **final Setup WNS ≥ +300 ps** + feedthrough + 是否一次布局布线成功）+ 资源数据记录 + git tag 存档
2. 功能分支开发，回归通过才合主线；主线永远保持可固化状态
3. 所有"魔法数字"（阈值、速度、灵敏度）一律走寄存器，禁止硬编码后重编译
4. 演示环境提前按比赛现场模拟：顶光、围观、连续运行 1 小时
