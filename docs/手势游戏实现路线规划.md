> 平台：HX1P35A 开发板（安路 PH1P35MDG324）
> 基线：基础要求已全部完成（MIPI 采集 → ISP → 边缘检测 → DDR2 → HDMI + OSD Logo）

## 0. 总体架构

```
SC500CS ─MIPI→ CSI解包 → ISP → [识别支路] → RAW/EDGE MUX → DDR2帧缓存 → [游戏/OSD渲染层] → HDMI TX
                                          │                                   ▲
                                          └─── 每帧少量结果（坐标 / 判定）──────┘

  [识别支路：CSI 域 ~59MHz，与像素域异步]        [游戏/OSD 渲染层：HDMI 像素域 75MHz]
   边缘检测(已有)          人体/手势跟踪链路(新增)      游戏引擎(vsync 节拍)
                           ├─ 肤色YCbCr掩码 ──┐         ├─ Pong
                           ├─ 运动掩码(背景差分)├─AND→融合掩码  ├─ 打砖块/贪吃蛇
                           ├─ 形态学去噪      ──┘         │   ├─ 切水果(精灵+粒子)
                           ├─ ROI门控包围盒/质心统计(相机域)   │   └─ 人体躲避框(掩膜碰撞)
                           ├─ 指尖提取(复用边缘图)         ├─→ 手部质心/指尖
                           └─ 轨迹状态机                   └─→ 形状窗口判定(相机域)
    取点：识别支路接在 isp_top 内部、RAW/EDGE MUX 之前（EDGE 模式下也必须仍有颜色）
    交互入口：手势质心·指尖 / 人物掩膜统计（KEY1 RAW-EDGE、KEY2/KEY3 曝光保持不变）
    键位分配：KEY4 短按 = 进入/退出手势模式，长按 = 一键示教；SW1~SW4 乒乓开关 = 参数在线调节
    显示背景与识别解耦：游戏层可叠在 RAW 或 EDGE 上（EDGE = 黑白线稿皮肤，零额外开销）
    可选拓展输入：IMU体感手柄(UART) —— 仅接入输入抽象层，不改游戏引擎
    兜底方案：荧光色指套（一键示教切换为色块跟踪，裸手失效时的 Plan B）
```

**核心原则**
1. 游戏渲染走"程序化渲染"（逐像素判属），挂在 hdmi_mixer 后级，不用 framebuffer
2. 所有模式切换在场消隐期发生，防画面撕裂
3. 游戏/OSD 层可整体旁路——基础视频链路任何时候独立稳定
4. 每完成一个里程碑必须编译实测，门禁见 §6：slices ≤85%（90% 红线）+ final Setup WNS ≥ +300 ps + feedthrough 不失控 + 一次布局布线成功
5. 输入抽象层从第一天就按"多源可插拔"设计——手柄日后作为纯增量接入，主线不为其等待
6. **融合掩码是一鱼两吃的核心资产**：降采样后供手部定位，全分辨率供躲避框碰撞检测（两个消费者都在 CSI 域）
7. **跨时钟域只交换每帧少量结果**：识别在 CSI 域、渲染在 HDMI 像素域（SDC 里两组时钟已设为异步），不传全帧掩膜；形状几何（像素域→CSI 域）与判定结果（CSI 域→像素域）各一条通路，并定义帧对齐策略

| 第 2 周 | M2 指尖/动态手势（含坐标对齐补偿）→ 支持 Pong/躲避框接入 → 贪吃蛇 | M3 收尾（手势接入 Pong 与菜单）→ M4a 切水果 → 打砖块 | M4c 人体躲避框（M1 就绪即开工）→ 配合 M5 菜单 |

| 弹性职责 | 跟踪链路的现场稳定性 | 游戏手感与演示效果 | 全队的备胎与保险丝：谁崩顶谁；X1 手柄的主人 |

**并行前提——第一天冻结五份接口契约**（三人一起，1~2 小时）：
1. 模式寄存器表（模式 ID + 场消隐期切换协议 + KEY4 短按=进出/长按=示教的键位约定 + 显示模式与游戏模式解耦）
2. **跨域接口契约（两域异步，不做全帧总线）**：①`ctrl_x / ctrl_y / valid` 每帧锁存（CSI 域 → 像素域）；②躲避框形状几何（像素域 → CSI 域，每帧一次）；③判定结果/填充率（CSI 域 → 像素域，每帧一次）；④帧对齐：判定帧定格 ≥3 帧，容忍 DDR 帧存带来的 ±1 帧错位
3. 掩码统计器接口（A 的 M0 产出，他人不依赖内部）
4. OSD 层级优先级表：**OSD 文字层（安路 Logo / 状态字 / 菜单）> 游戏层 > 摄像头背景**——基础要求 4 的 Logo 与算法状态字在任何模式下都必须可见，游戏层不能盖住它们
5. 资源配额分账（≤85% 封顶，合计 3900 LUT6）：A ≈1400（M1+M2），B ≈1200（M3+M4a），C ≈1200（M0+M4b+M4c+M5），机动 100，谁超支谁自己找回来
6. **文件所有权、四个插座与硬件资源账本（§2.5）**——第一天一起过一遍并各自留档；跨人改文件一律提需求给 owner

**协作纪律**：每人一个功能分支，主线永远可固化；每两天一次短会同步接口/资源/进度；联合调试成对半天进行（M1→Pong、M1→躲避框、引擎→砖块、最终整合），不搞大爆炸式整合。

## 2.5 并行协作与资源账本（2026-09-13 新增）

三人并行最大的风险不是写不出模块，而是**抢同一份文件、抢同一块硬件、抢同一个时钟域**。§2 的接口契约之外，这一节是签字版约定：所有权、插座、账本、集成流程。

### 2.5.1 文件所有权

| 文件 / 目录 | owner | 说明 |
|---|---|---|
| `design_top_wrapper.v`、`hdmi_mixer.v`、`alg_switch.v` + KEY4/模式寄存器模块 | **C** | 顶层、集成、渲染图层 |
| `user_source/constraints_source/*`、`td_project/camera_to_dsi_display.sdc` | **C** | 引脚与时序约束 |
| `camera_to_dsi_display.al` + 两个 Run 目录的 `camera_to_dsi_display.prj` / `settings.cfg` | **C** | 新增源文件的登记只能 C 做 |
| `debug_uart_logger.v` | **C** | A/B 只提"字段申请"（位宽 + 含义），不自己改编码表 |
| `eram_spram.v`、`anlogic_logo_rom.v`、`osd_char_lib.v` | **C** | 共享原语与只读资产（字模只读，要新字符各自建表） |
| `isp/**`（含 `isp_top.v`、`edge_detect_96.v`） | **A** | 识别支路取点、窗口生成器拆分 |
| `hdl_source/game/**`（新建目录） | **B** | 游戏层、菜单、精灵 ROM |
| `README.md`、`docs/*` | 分节 owner | CHANGELOG 追加式写入，避免同段冲突 |

四条硬规则：

1. **跨人改文件 = 提需求给 owner**，不许自己动手；owner 改完回一句"改在哪个文件哪一行"。
2. **`hdmi_mixer.v` 归 C，游戏逻辑必须放 B 自己的模块里**——mixer 只允许 C 加"实例化 + 图层 mux"，B 不碰这个文件（否则 B 的活儿天天和 C 抢同一个文件）。
3. **新增 `.v` 必须由 C 一次性登记进 `.al` + 两个 `prj`**：2026-09-13 踩过，`eram_spram.v` 漏登记，综合直接报 `HDL-8007 black box`。
4. **SDC 是每条新跨域路径的守门人**：新增跨时钟域通路（形状几何 pixel→CSI、判定结果 CSI→pixel）必须同时由 C 加约束（`set_max_delay -datapath_only`），否则时序报告不可信——这类问题会静默出错，比编不过更危险。

### 2.5.2 四个插座（编译期固定，接口冻结）

| 插座 | 时钟域 | 端口约定 | 定接口 / 实现 |
|---|---|---|---|
| VIDEO_TAP | CSI ~59 MHz | 96bit/4px + tuser/tlast/tvalid，**位置在 `isp_top` 的 MUX 之前**；同时引出 edge 输出 | C 定 / A 用 |
| RENDER_SLOT | 像素域 75 MHz | x/y/de/vsync + 24bit pixel_in → 24bit pixel_out（daisy-chain） | C 定 / B 实现 |
| PARAM_BUS | 统一挂像素域 | `param_we / param_addr[7:0] / param_data[15:0]`；地址分段 0x00~0x3F 系统、0x40~0x7F A、0x80~0xBF B、0xC0~0xFF C | C 定地址表 |
| CTRL_SYNC | 跨域 | 每帧一个字 `{valid, x[10:0], y[10:0], state[3:0]}`，上下行各一条 | C 定编码 |

- 数据流顺序固定为 **DDR → RENDER_SLOT（B 的游戏层）→ OSD 文字/Logo 层（C）→ HDMI**：游戏层永远在文字层下面，想遮安路 Logo 都遮不了（基础要求 4 天然满足）。
- **插座少而固定**：feedthrough 已经 6767（官方 720P 例程约 2400），每加一组顶层连线都在加剧拥堵，禁止"每个功能拉一把新线到顶层"。
- **不做运行时插拔/枚举**：编译期固定 + 一个整体旁路开关即可，运行时可变只会变成额外的 mux 和时序债。
- M0 一次做完：四个插座 + 旁路 mux + `I_button[2:0]` → `[3:0]`。

### 2.5.3 硬件资源账本

当前实测（2026-09-13）：LUT6 10809 / 21216、slices 13214（62.28%）、ERAM 70 / 108、DSP 8 / 40。

| 资源 | A 视觉 | B 游戏 | C 集成/验证 | 机动/保留 | 规则 |
|---|---|---|---|---|---|
| LUT6 | 1400 | 1200 | 1200 | 100 | 总新增 ≤3900（85% 封顶），超支自己找回来 |
| ERAM | 8 块 | 10 块 | 2 块 | **18 块不分配** | 按"位宽×深度"几何申请，一次领一块 |
| DSP | 8 | 8 | 2 | 14 | YCbCr 矩阵 / 距离平方 / 物理积分类 |
| 引脚 | 0 | 0 | 全部 | — | 新引脚一律 C 登记（见下） |
| 时钟域 | 只准在 CSI 域加逻辑 | 只准在像素域加逻辑，**且必须打拍** | CDC 与 SDC 归 C | — | 任何人不得新增 PLL / 时钟 |

引脚登记清单（M0 落地）：

- KEY4 = **C7**（顶层端口扩到 `I_button[3:0]`）
- 乒乓开关 SW1~SW4 = **A4 / B4 / E11 / D11**（参数在线调节）
- UART 接收 RXD = **J1**（现在只约束了 TXD = H1）
- 蜂鸣器 BUZZER = **C12**（低电平响；中间还有 SW5 物理开关）
- 4 个独立 LED = **D10 / E10 / C6 / D6**（不复用，推荐做"手势→外部控制"的落点）
- 8 位数码管与 8 组双色 LED **共用同一组 16 个引脚、由 SW6 二选一**（拨上=数码管，拨下=双色 LED）——所以"数码管显示延迟"与"双色 LED 做外部控制"不能同时用，扩展 3 请用独立 LED + 蜂鸣器。

### 2.5.4 集成流程

- **C 是唯一合并人**；`main` 只在"能一次跑通 `tools/build_td.ps1`"时前进；每人合并前自己先跑一次完整构建。
- **集成窗口**：每天固定一次批量集成，C 一次处理完当天的合并与资源登记，避免随时被打断。
- **`tools/new_worktree_runs.ps1`**：一键铺好新 worktree 的 Run 目录，并自动补两个已知补丁（`eram_spram.v` 登记 + `phy_1/settings.cfg` 的 `place opt_timing high`），否则每开一个 worktree 都可能重演"综合报 black box"。
- **模块自证注释**：每个模块头必须写清"延迟几拍 / 跨不跨域 / 要不要 SDC 约束 / 占多少 ERAM·DSP"，既给队友看，也是报告的现成素材。

**目标：为后续所有功能铺路，不加任何新功能**

### M1 融合掩码跟踪链路（4~5 天，A）

**目标：得到一张"干净的人/手掩膜"——这是所有交互功能的地基**

肤色检测单用不靠谱（类肤色背景、光照漂移、脸手干扰），采用**肤色 ∩ 运动 双掩码融合**架构：

- [ ] RGB→YCbCr 转换（3×3 常系数矩阵，**乘法用空闲 DSP**）
- [ ] 肤色阈值掩码（Cb/Cr 双区间判定），阈值寄存器可在线调
- [ ] **运动掩码**：背景帧差分 + 阈值
  - 背景帧：降采样灰度图存 ERAM（128×75×8bit ≈ 75Kbit；块数按"位宽×深度"几何核算后确认，别直接按 bit 数 ÷ 20Kb 估），绕开 DDR2 带宽
  - 背景更新：KEY4 长按采样（演示前按一下，可控性最强）；可选每帧 1/16 缓慢自适应
- [ ] 双掩码按位与 → 融合掩码：肤色背景"是肤色但不动"被杀，衣物摆动"在动但非肤色"被杀
- [ ] 形态学开运算去噪（复用 M0 窗口生成器）
- [ ] **ROI 跟踪门控**：锁定后只在上帧包围盒外扩窗口内统计，窗口外干扰物理隔离；掩码像素数低于阈值连续 N 帧 → 退回全帧重新搜索
- [ ] 统计器输出：包围盒 + 质心 + 掩码像素计数
- [ ] 时域滤波：质心 α-β 滤波 + 丢失保持（丢帧维持最后位置 ≤5 帧）
- [ ] OSD 十字准星 + 包围盒叠加（复用现有 OSD 通道）
- [ ] **一键示教**（双用途，KEY4 长按触发）：第一次长按采样手部 Cb/Cr 均值/方差更新肤色阈值，第二次长按采样背景帧（两段式，防误触）
- [ ] （可选）投影直方图选峰：融合掩码存在多个独立区域时，x/y 投影选最大峰，替代昂贵的连通域标号（~200 LUT6）
- [ ] **识别结果接进 `DBG:`**（README 点名开工前必须定的事）：掩码像素数、包围盒 min/max、质心、手型状态、手势事件计数，沿用现有"相机域统计 → 帧首锁存 → 2 级同步 → 显示域 logger"模式（`M` 与 `D/E/W/V` 就是这么做的）
- [ ] 示教与运行日志同行输出 `A`/`G`（曝光/增益）与掩码统计，现场翻车也能靠日志复盘
- [ ] 记一条前提（2026-09-13 核实）：**AE/AG 是手动按键设定的**（`ae_set` 只在按键时改 `r_ae_set`/`r_ag_set`，不会自己漂），**AWB 才是自适应的**（`awb.v` 每帧统计 RGB 均值、用除法器算增益再乘回像素）——换光照或画面里出现大面积肤色物体时白平衡会动，所以示教要按现场光照做，并把示教瞬间的 `A`/`G` 记进日志

**全身/手部双模式**：摄像头近景拍手 → 手部跟踪（游戏操控）；拉远拍全身 → 人物掩膜（躲避框）。同一套链路，只是取景和统计窗口不同。

验收：演示者穿短袖，正常室内光下准星跟手流畅；背景出现木桌/人脸不干扰；换光照一键示教 3 秒恢复；目标出画 5 帧内丢失、回画 3 帧内重新锁定。
**编译实测 #1**，记录实际增量（slices / LUT6 / ERAM / WNS），按 §6 门禁检查。
**Plan B 备案**：指尖戴荧光色指套，一键示教切换为色块跟踪——裸手方案现场失效时的兜底（不算作弊，一键示教本就支持任意颜色目标）。

- [ ] 轨迹状态机：左挥 / 右挥 / 下劈（质心位移 + 速度 + 加速度阈值），手势事件脉冲输出

### M3 游戏引擎框架 + Pong（3~4 天，B）

**目标：第一个可玩游戏**

- [ ] 游戏渲染层框架：层级优先级 mux（**OSD 文字层 > 游戏层 > 摄像头背景**），逐像素矩形判属函数
- [ ] 游戏逻辑时钟域：全部挂在像素时钟域，**vsync 为游戏节拍**（60Hz 固定步长）

### M4c 人体躲避框 / Human Tetris 变体（2~3 天，C，M1 完成后即可开工）

**核心机制**：屏幕生成运动的镂空形状窗口 → 玩家用身体穿过/避开 → 定格瞬间做掩膜碰撞判定。

**技术本质：二值掩膜碰撞检测**——不识别"是谁/什么姿势"，只判"这个像素是不是人"与"人和框有没有重叠"。直接消费 M1 的全分辨率融合掩膜（**同一 CSI 域内**，不做跨域全帧总线），这是该项目与手部跟踪共享地基的原因。

- [ ] 形状窗口生成器：镂空矩形（外框 - 内洞），参数化（位置/大小/洞形），从屏幕顶端下落或侧面推近（缩放模拟逼近）
- [ ] 碰撞统计（在相机域、vsync 节拍）：
  - **越界计数**：人物掩膜落在"墙体区"（外框内 - 洞外）的像素数 → 超过阈值 = 撞到
  - **填充率**：人物掩膜落在"洞内"的像素占比 → 评分依据（填充越满分越高）
  - **跨域与帧对齐**：形状几何由像素域每帧写入 CSI 域，判定结果每帧读回；判定帧定格 ≥3 帧，容忍 DDR 帧存造成的 ±1 帧错位
  - **判定用哪一帧要写死**：判的是"当前相机帧"、显示的是 1~2 帧前的画面——定格足够久，这点误差就看不出来
- [ ] 游戏流程状态机：预告 → 形状逼近 → 定格（freeze 判定帧）→ 判定 → 计分 + 特效（通过=绿闪+粒子，撞到=红闪+震动音效/蜂鸣器）
- [ ] 难度递进：形状下落速度加快、洞形变小、连续组合
- [ ] OSD：分数、连击数、判定结果大字动画
- [ ] 取景要求：摄像头拉远拍全身，演示区预留 2~3 米纵深——彩排时确认场地

**为什么这个游戏性价比极高**：渲染只有矩形（零精灵）、判定只是两个计数器，总计 ~300~400 LUT6；但它是全身交互，围观效果和搞笑程度全场第一——日本综艺《人体俄罗斯方块》的综艺感就是它的演示效果。

验收：不同体型人员实测判定准确；定格判定无延迟感；连续 10 局无状态机卡死。

### M5 延迟可视化 + 系统整合（2~3 天，C 牵头）

**目标：一个固化镜像装下所有功能**

## 6. 工程纪律

1. 每个里程碑结束：编译实测（slices / LUT6 / ERAM / DSP + **final Setup WNS ≥ +300 ps** + feedthrough + 是否一次布局布线成功）+ 资源数据记录 + git tag 存档
2. 功能分支开发，回归通过才合主线；主线永远保持可固化状态
3. 所有"魔法数字"（阈值、速度、灵敏度）一律走寄存器，禁止硬编码后重编译
4. 演示环境提前按比赛现场模拟：顶光、围观、连续运行 1 小时
5. 文件所有权、插座契约与资源账本见 §2.5：跨人改文件一律提需求；每人合并前先自己跑一次 `tools/build_td.ps1`
