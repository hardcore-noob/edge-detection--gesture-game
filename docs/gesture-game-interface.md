# 手势游戏接口与验收

本文是手势识别、集成层和切水果之间的接口契约。README 只保留摘要；参数行为、
上板玩法和测试清单以本文为准。

## 数据流

```text
MIPI -> ISP -> VIDEO_TAP（CSI 域识别）
                   |
                   v
           toggle + 整包捕获
                   |
                   v
DDR -> RENDER_SLOT -> game_top -> OSD -> HDMI
```

识别坐标和状态来自 `VIDEO_TAP` 的观测包，参数由 `PARAM_BUS` 写入，
算法类模式由 `MODE_SYNC` 在相机帧首提交。

## 插座

| 插座 | 时钟域 | 约定 |
|---|---|---|
| `VIDEO_TAP` | CSI ~59 MHz | 96 bit/4 px，含 tuser/tlast/tvalid |
| `RENDER_SLOT` | 像素域 75 MHz | DDR 读回 → 游戏层 → OSD；边界 0 拍组合 |
| `PARAM_BUS` | 像素域 | 单拍写，地址低 6 位转发到 B 段 |
| `CTRL_SYNC` | 跨域 | 每帧 26 位，toggle 握手 |
| `MODE_SYNC` | 像素域 → CSI | 算法类寄存器在相机帧首提交，带回执 |

### VIDEO_TAP 观测包

总宽度 76 位：

| 字段 | 宽度 |
|---|---:|
| tap 每帧像素数 `>>10` | 12 |
| 掩码像素数 `>>4` | 16 |
| bbox x | 14 |
| bbox y | 12 |
| 追踪 x | 11 |
| 追踪 y | 10 |
| track_locked | 1 |

### CTRL_SYNC

- 下行：形状描述子 `{shape_type, progress, hole_w, hole_h, variant}`。
- 上行：判定结果 `{verdict, viol_cnt, fill}`。
- 墙/洞坐标由两域共享的只读 `shape_gen.v` 各自计算，不跨域传输。

### MODE_SYNC

当前 26 位布局：

| 位 | 字段 |
|---|---|
| `[3:0]` | `edge_th_sel` |
| `[7:4]` | `display_mode` |
| `[11:8]` | `game_mode` |
| `[15:12]` | `recog_algo` |
| `[19:16]` | `teach_cnt[3:0]` |

算法类寄存器在相机帧首提交；像素域 OSD 和 DBG 使用回执值。

## 跨域规则

1. 发送侧同拍锁存数据和 toggle。
2. 接收侧两级同步 toggle，再做边沿检测。
3. 检测到边沿后整包捕获数据，不逐位同步多比特总线。
4. CSI 与 HDMI 像素时钟属于异步组，TD 不检查其间路径，正确性由握手结构保证。

## 系统参数地址

| 地址 | 名称 | 读写 | 说明 |
|---|---|---|---|
| `0x00` | `display_mode` | R/W | 0=RAW，1=EDGE |
| `0x01` | `game_mode` | R/W | 0=关，1=GES |
| `0x02` | `edge_th_sel` | R/W | TH = 16 + 4×sel |
| `0x03` | `teach_req` | W1P | 示教已移除，写入仍计数 |
| `0x04` | `teach_cnt` | RO | 示教请求累计 |
| `0x05` | `key4_evt` | RO | `{长按次数, 短按次数}` |
| `0x06` | `param_wr_cnt` | RO | 成功写入次数 |
| `0x07` | `mode_commit_cnt` | RO | 模式提交次数 |
| `0x08` | `recog_algo` | R/W | 0=停，1=识别，8..15=调试档 |

## B 段参数

| 地址 | 名称 | 默认值 | 说明 |
|---|---|---|---|
| `0x80` | `game_sel` | 1 | 1=切水果 |
| `0x81` | `game_ctrl` | 0 | bit0 重开、bit1 待机、bit2 关层、bit3 暂停 |
| `0x85` | `input_src` | 1 | 0=假源，1=手势，2=UART 手柄预留 |
| `0x86` | `input_cfg` | 0 | `{假源档位, 死区}` |
| `0x87` | `input_gain` | 0x0100 | 保留，未参与运算 |
| `0x88` | `input_offset` | 0 | 手势源 x/y 有符号偏置 |
| `0x89` | `fruit_spawn` | 48 | 水果生成间隔 |
| `0x8A` | `fruit_grav` | 0x0040 | 重力 |
| `0x8B` | `fruit_v0` | 0x0900 | 垂直初速/水平散布 |
| `0x8C` | `trail_cfg` | 0x080A | 刀光参数，编译关闭 |
| `0x8D` | `particle_cfg` | 0x0814 | 粒子寿命，已启用 |
| `0x8E` | `field_y0` | 200 | 场地上边界 |
| `0x8F` | `field_y1` | 704 | 漏切判定线 |
| `0x90` | `state_word` | RO | `{state[3:0], 3'b0, score_neg, score_bcd[7:0]}` |
| `0x91` | `blade_pos` | RO | `{x>>3, y>>3}` |
| `0x92` | `fruit_pos` | RO | 1 号水果 `{x>>3, y>>3}` |
| `0x93` | `hit_cnt` | RO | 切中计数 |
| `0x94` | `miss_cnt` | RO | 漏切计数 |
| `0xA0` | `dbg_blade_x` | 640 | UART 直给刀尖 x |
| `0xA1` | `dbg_blade_y` | 400 | UART 直给刀尖 y |
| `0xA2` | `dbg_blade_en` | 0 | UART 直给使能 |
| `0xA3` | `dbg_marker_en` | 0 | 5 点坐标对齐标记 |

未登记地址读回 `0xFFFF`。`0x95` 已移除。

## 串口命令

```text
W 00 0001      # 切到 EDGE
W 01 0001      # 打开游戏层
W 02 0003      # 门限档位 3，TH=28
W 08 0001      # 单独启用手势识别
W 81 0001      # 重开本局
W 81 0004      # 暂停
W 81 0002      # 回待机
W 85 0000      # 回假源
W 85 0001      # 切回手势源
W A3 0001      # 打开坐标对齐标记
```

## 当前切水果规则

- 水果显示和碰撞箱为 128×128。
- AABB 半宽 64 + 刀锋外扩 10，中心阈值 ±74。
- 使用 8 个刀锋历史点和 16 个插值采样点。
- `cut_enable = blade_valid && track_locked && input_src==1`。
- `cut_enable` 上升沿用当前刀尖填满历史，下降沿清空。
- 左右挥切生成上下半片；上下挥切生成左右半片。
- 切中水果 `+1`，漏掉水果 `-1`；切中炸弹 `-5`，漏掉炸弹不扣分。
- 分数为有符号两位 BCD，范围 `-99..+99`；不再使用生命值或结束态。
- 炸弹每次生成约 12.5% 概率，同屏最多一颗；命中后触发橙红色基础爆散。
- 半片字段：`pal[3]=A/B侧`、`pal[2]=负x`、`pal[1:0]=水果种类`、
  `color[6]=切割轴`；普通水果对象的炸弹标志也复用了 `pal[3]`，只在
  `type=2` 时解释为炸弹。
- 左侧完整出屏条件为 `x<=-128`；右侧为 `x>=1280`。

## 上板测试清单

1. RAW/EDGE、KEY1、KEY2/KEY3 和基础 OSD 正常。
2. KEY4 进入游戏后无需串口即可使用手势源。
3. `W 85 0000` 可移动假源刀锋但不计分，`W 85 0001` 恢复手势计分。
4. 左挥和右挥均生成上下半片。
5. 上挥和下劈均生成左右半片。
6. 单颗命中应显示对应方向的两片，不出现左右侧别串用。
7. 左侧水果逐渐裁剪到完全出屏，右侧同样完整出屏后回收。
8. 一帧命中多颗时分数和 `hit_cnt` 正确。
9. 手离开并重新锁定后，历史点从当前刀尖重填，不跨屏补切。
10. 水果命中显示黄色粒子；漏水果、切炸弹和两者同帧时分数分别正确变化。
11. 炸弹为高对比精灵，命中后不出现半片，显示橙红色大粒子爆炸。
12. 只漏掉炸弹不扣分，游戏不会因分数变负而结束。
13. DBG 的 `U=0x0384`，CTRL_SYNC 往返常数为 `X=0x00a5`、`Y=0x00d3`。
