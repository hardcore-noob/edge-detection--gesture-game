## 3. M1 执行清单（原文档 §3 M1 逐条）

**目标：得到一张"干净的人/手掩膜"——所有交互功能的地基。**
单用肤色不靠谱（类肤色背景、光照漂移、脸手干扰），所以走 **肤色 ∩ 运动** 双掩码融合：

- [ ] 肤色判定：**不做 3×3 全矩阵乘法**（4 px/拍 × 9 乘 = 36 乘/拍，8 个 DSP 远远不够）。
      走 **`(B−Y)` / `(R−Y)` 双区间判定**——由 `Cb = 0.564(B−Y)+128`、`Cr = 0.713(R−Y)+128`
      可知它与 Cb/Cr 双区间**完全等价**；Y 复用现成的 `R/4+G/2+B/4`，**在 `recog_top` 里重算一份，
      别去改 edge 模块**。成本：每像素 2 减法 + 4 比较 ≈ **100~150 LUT6，0 DSP**。
- [ ] 肤色掩码阈值：**按 `R/4+G/2+B/4` 在板上重新标定**（不要抄教科书的 Cb/Cr 数值），
      上下限经 PARAM_BUS 在线调（**A 段 0x40~0x7F** 预留给肤色上下限 / 运动阈值 / quiet_th）
- [ ] **运动掩码**：背景帧差分 + 阈值
  - 背景帧：**80×45 灰度图**（/16 双轴，1280/16=80、720/16=45 都整除）存 ERAM，
    28.8 Kbit ≈ **2 块**。好处：①整除、行映射均匀；②块索引就是 `x[10:4]`/`y[9:4]`，纯位切片；
    ③一块 16 px 正好是 4 个"4 像素/拍"的组，**每拍只需 1 次背景读**。
    代价：块均值更糊 → 高对比边缘附近假运动变多，靠肤色 AND + 阈值现场调吸收。
    备选 128×72（/10，≈5 块），上板若发现 /16 太粗再切。
  - 背景更新：**KEY4 长按手动采样为主**；自适应只作兜底，且必须"**quiet 门控 + 限速蠕变**"：
    只有 `|当前块均值 − 背景块均值| < quiet_th` 的块才允许更新，且 `quiet_th < motion_th`
    （例 4 vs 8，形成滞回）；每块最多每 64 帧动 1 LSB（等效时间常数几十秒）。
    **"每帧 1/16"作废**（60 fps 下时间常数只有 ≈0.27 s，静止的手 0.3 秒就被吸进背景）。
    实现上别给每块配 N 帧计数器（3600 个 ≈1 块 ERAM），用全局帧计数低位 + 块索引挑帧即可；
    更新放在**场消隐期**（CSI 域有 ≈4.7 ms 空闲），不与像素流抢单口 ERAM 的读写。
- [ ] 双掩码按位与 → 融合掩码（肤色背景"是肤色但不动"被杀；衣物摆动"在动但非肤色"被杀）
- [ ] 形态学开运算去噪：**新建 `mask_win_3x3.v`**（结构照抄 `edge_win_3x3_96` 的三块行轮转，
      数据通路是 1bit × 6 列 × 3 行）。**不能直接复用 `edge_win_3x3_96`**（那是 96bit 进、
      48bit 平滑灰度窗口出的彩色/灰度专用模块，掩膜用不了，也不该给已验证的边缘路径加参数）。
      估 150~250 LUT6
- [ ] **ROI 跟踪门控**：锁定后只在上帧包围盒外扩窗口内统计；掩码像素数连续 N 帧低于阈值 → 退回全帧重搜
- [ ] 统计器输出：包围盒 + 质心 + 掩码像素计数
- [ ] 时域滤波：质心 α-β 滤波 + 丢失保持（丢帧维持最后位置 ≤5 帧）
- [ ] OSD 十字准星 + 包围盒叠加（复用现有 OSD 通道）
- [ ] **一键示教**（KEY4 长按，两段式防误触）：第一次长按采样手部 (B−Y)/(R−Y) 的
      **min/max 包络**并加余量作为肤色上下限（**不用均值/方差**——方差要累加平方、成本高且不好现场解释），
      第二次长按采样背景帧
- [ ] （可选）投影直方图选峰：多区域时 x/y 投影选最大峰，替代连通域标号。
      **成本上修：1~2 块 ERAM + 300~500 LUT6**；**只有 M2 之后实测仍有余量才做**，否则直接砍掉
- [ ] **识别结果接进 `DBG:`**：掩码像素数、包围盒 min/max、质心、手型状态、手势事件计数
      （沿用"相机域统计 → 帧首锁存 → 2 级同步 → 显示域 logger"的模式，`M` 和 `D/E/W/V` 就是这么做的）
- [ ] 示教与运行日志同行输出 `A`/`G`（曝光/增益）+ 掩码统计，现场翻车能靠日志复盘

**A 的 LUT6 分项（v1.8 官方估算，合计 ≈1410）**：肤色判定 150 + Y 重算 50 + 背景差分与地址 150 +
背景更新控制 100 + 融合与形态学 200 + ROI/统计 150 + 时域滤波 120 + 指尖/轮廓记忆 250 +
轨迹与手型 120 + 示教与 DBG 120；**可选直方图的 300~500 不计在内**——做了就超 A 的 1400，
必须先看那次构建的余量或砍别的。

**前提核实（原文档已定）**：AE/AG 是**手动按键**设定的（`ae_set` 不会自己漂），**AWB 才是自适应的**
（`awb.v` 每帧统计 RGB 均值、用除法器算增益再乘回像素）→ 换光照或画面里出现大面积肤色物体时白平衡会动，
所以示教必须按现场光照做，并把示教瞬间的 `A`/`G` 记进日志。

**双模式**：近景拍手 = 手部跟踪（游戏操控）；拉远拍全身 = 人物掩膜（躲避框）。同一套链路，只是取景与统计窗口不同。

## 5. 必须遵守的接口契约（§2.5.2 四个插座）

| 插座 | 我这边要做的事 |
|------|----------------|
| **VIDEO_TAP**（CSI 域，实现位置 `isp/recog_top.v`） | 取点在 `isp_top` 内部、**RAW/EDGE MUX 之前**（AWB 彩色流 + 边缘流）。**不要把 96 位流拉到顶层**，对外只引：`O_tap_px_shift[11:0]`（每帧像素数>>10，应恒为 `0x384`）、`O_mask_cnt_shift[15:0]`、`O_bbox_x[13:0]`、`O_bbox_y[11:0]`、`O_status_toggle`（每帧翻转，像素域据此整包捕获）+ CTRL_SYNC 端点 |
| **CTRL_SYNC**（CSI ↔ 像素域，**v1.8 已冻结字义**） | 每帧一个字 **26 位**（"每帧一次"由 toggle 表示，字内不占比特）：**下行（像素域→CSI 域）= 参数化形状描述子** `{shape_type[2:0], progress[7:0], hole_w[5:0], hole_h[5:0], variant[2:0]}`；**上行（CSI 域→像素域）= 判定结果** `{verdict[1:0], viol_cnt[11:0], fill[11:0]}`。墙/洞坐标由共享 `shape_gen.v` 在两域各算一次，**不传 x/y/w/h**（一个矩形要 42 位，装不下还容易和渲染错位）。`ctrl_sync.v` 已加 `WIDTH` 参数 |
| **PARAM_BUS**（像素域） | 我的寄存器段是 **0x40~0x7F**，v1.8 已预留给**肤色上下限 / 运动阈值 / quiet_th**；写源优先级 UART > KEY4 长按 > KEY4 短按 > KEY1 > 拨码 |
| **RENDER_SLOT** | 是 B 的地盘，我只消费它，不改 |

## 6. 必须记住的坑（§2.5.1 实测结论）

1. **跨域正确性靠握手设计，不靠 SDC**：TD 会忽略异步组之间的 `set_max_delay`（`camera_to_dsi_display_exception.timing` 里标成 `Set Max Delay (Ignored)`，把 5 ns 改成 15 ns 所有数字一个没变）。正确性靠：发送侧数据与 toggle **同拍锁存** → 接收侧两级同步 + 边沿检测后**整包捕获**（绝不逐位同步多比特）→ 上板用 `DBG:` 验证。
2. **帧级统计相位**：`awb.v` 的 tuser 是**直通**的、valid 是流水后的且行间有空隙，**tuser 脉冲常落在 valid=0 的拍上** → 任何帧级计数/锁存都要"**计数按 valid、锁存按 tuser**"，跨域 toggle 也只认 tuser（2026-09-15 上板踩到：`U/P/Q/R` 恒 0 而画面完全正常）。
3. **24 m ↔ 像素域**在同一个异步组里，照常按普通路径算，必须靠打拍/RTL 满足。
4. 只加 CSI 域逻辑；不得新增 PLL / 时钟。
5. 所有"魔法数字"（阈值、灵敏度）一律走寄存器，禁止硬编码后重编译。
6. 模块头注释必须写清：**延迟几拍 / 跨不跨域 / 要不要 SDC 约束 / 占多少 ERAM·DSP**。
7. **`phy_1/settings.cfg` 的布局参数必须按值校验**：`place opt_timing high` **和** `place max_fanout 250` 两个都要在
   （`new_worktree_runs.ps1` 现在按值检查并会就地替换）。缺 `max_fanout 250` 会**静默少 222 ps 余量**
   （2026-09-17 实测：只有 `opt_timing high` 时 WNS +654 ps，两个都有才是 +876 ps）。
8. **背景差分 ≠ 帧间差分**：用背景帧差分时，静止的手只要没被吸进背景就一直"与背景不同"，所以静止手势不会丢；
   前提是背景更新必须走 quiet 门控（见 §3），绝不能无条件自适应。
