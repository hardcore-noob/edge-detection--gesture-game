# FPGA 连通域与区域生长项目调研（2026-10-29）

> 目的：为现有 1280×720、4 px/周期、CSI 约 59 MHz、ERAM 只剩 32 块的
> 手部掩码筛选链路，寻找可借鉴的 FPGA CCL / region growing 实现。
> 只采用能读到源码或正式项目文档的一手来源。

## 0. 结论

按与本工程的匹配度排序：

1. **LinkRunCCA**：最值得借鉴。单遍、run-length + linked list、最多
   1 pixel/cycle，不保存整帧标签，直接输出每个连通块 bbox；
2. **Kryon CCAL**：单遍流水线，只缓存一行，直接输出面积和 bbox；
   但 180-bit shape table 很重，且作者明确承认复杂形状会漏统计；
3. **ylemiesa57 的 tpss_ccl_8conn**：结构最完整、最容易理解的两遍扫描 +
   address-based union-find；但为 ROI 内每个像素保存父指针，默认
   `708×146` 就要约 1.96 Mbit 父指针表，不适合直接搬到全分辨率；
4. **tthien22 Region-Growing-Verilog**：写了 8 邻域 BFS 区域生长，但代码使用
   `initial`、`$readmemh`、文件 I/O、全帧二维数组和不受约束的循环，实际是
   Verilog 仿真程序，不是可综合 FPGA RTL。

另外找到一个短小的单遍 union-find 示例
[niuwe/connect_domain_fpga](https://github.com/niuwe/connect_domain_fpga)，
但它的行缓存深度被硬编码为 10、等价表只配置 32 项，默认参数只适合 10×10
仿真，不应作为可直接移植的生产代码。

对本工程最合适的路线是：**在 80×45 或 160×90 的块级二值图上运行
LinkRunCCA 类算法，只输出少量候选的 bbox/面积/运动量，再用上一帧位置选择
手部，不必生成全分辨率标签图。** 它比“每像素保存标签 + 第二遍遍历”更接近
当前资源和时序限制。

## 1. LinkRunCCA（OpenCores / Verilog + VHDL）

- 项目：
  - [源码镜像](https://github.com/Topi-ab/linkruncca)
  - [README](https://github.com/Topi-ab/linkruncca/blob/main/README.txt)
  - [`LinkRunCCA.v`](https://github.com/Topi-ab/linkruncca/blob/main/src/verilog/LinkRunCCA.v)
  - [`table_reader.v`](https://github.com/Topi-ab/linkruncca/blob/main/src/verilog/table_reader.v)
  - [`equivalence_resolver.v`](https://github.com/Topi-ab/linkruncca/blob/main/src/verilog/equivalence_resolver.v)
  - [`feature_accumulator.v`](https://github.com/Topi-ab/linkruncca/blob/main/src/verilog/feature_accumulator.v)
  - [`holes_filler.v`](https://github.com/Topi-ab/linkruncca/blob/main/src/verilog/holes_filler.v)
- 许可证：LGPL-3.0。

### 实现逻辑

- 输入是二值视频流 `pix_in + datavalid`，设计目标是最高 1 pixel/cycle；
- 使用 **run-length + linked list**，对一个 run 建标签，并维护
  Head、Tail、Next、Data 四张表；
- 四张表都是简单双口 RAM：
  - Head / Tail / Next：地址位宽；
  - Data：保存 bbox；
- 两个 `row_buf` 分别服务于 hole filler 和 2×2 邻域窗口，逻辑上只需
  上一行；
- `holes_filler.v` 用非常便宜的局部规则填孔：
  `top && (left || right)`；
- `equivalence_resolver.v` 在 run 结束、run 合并等事件上更新链表和等价关系；
- `feature_accumulator.v` 将每个完成 run 的坐标并入 bbox，组件结束时立即
  输出 `box_out = {min_x,max_x,min_y,max_y}` 和 `datavalid_out`；
- README 默认图像参数是 `imwidth=512, imheight=512`，但代码参数化；
- 顶层地址宽度使用 `x_bit-1`。二值图中每两个像素最多形成一个前景 run，
  所以表项数按约半行宽配置。

### 资源判断

`table_ram.v` 中每张表是独立的双口 RAM。对 512×512 默认配置估算：

- `x_bit=9, y_bit=9, address_bit=8, data_bit=36`；
- Head/Tail/Next 各 `256×8 bit`；
- Data `256×36 bit`；
- 四张表合计 `15,360 bit`；
- 两个 510-bit 行移位缓存合计 `1,020 bit`。

理想容量不足 1 块 ERAM20K，但四张独立小 RAM 的物理映射通常会各占资源，
需要综合确认。即使把宽度扩到 1280，四张表加两个行缓存也只有约
`76 Kbit` 的理想容量，量级仍然可控。

### 可借鉴

- **不保存全图标签**，适合我们当前 ERAM 紧张的状态；
- 1 pixel/cycle 的流式吞吐适合处理已降采样的块图；
- 输出 bbox 的时机与组件结束同步，不需要第二遍图像扫描；
- 同一结构可增加面积、运动像素数等 Data 字段。

### 局限

- 默认数据表只存 bbox，不算面积、质心或运动量；需要扩 Data 位宽；
- run/链表合并依赖较多随机表访问，需要仔细检查 BRAM 端口和时序；
- 许可证是 LGPL-3.0。若要直接复用代码，应先按团队/赛题规则确认许可证；
  更稳妥的是只借鉴算法结构并自行实现。

## 2. Kryon CCAL（FPGA，Verilog）

- 项目：
  - [仓库](https://github.com/DavisLiao/Kryon)
  - [`CCAL.v`](https://github.com/DavisLiao/Kryon/blob/master/FPGA%20Image%20Process.v/CCAL.v)
  - [`LineBuffer.v`](https://github.com/DavisLiao/Kryon/blob/master/FPGA%20Image%20Process.v/LineBuffer.v)
- 许可证：Apache-2.0。

### 实现逻辑

- 模块输入 `Vsync / DataEn / BinaryData`，处理二值像素流；
- README 明确说明它采用并行流水线，只需缓存一行图像，不需要 DDR；
- `CCAL.v` 使用相邻的 left、up-left、up、up-right 标签：
  - 没有邻域标签时分配新标签；
  - 只有一个邻域标签时继承；
  - 两个不同标签时合并形状信息，并把合并后的信息写回旧标签；
- 每个标签的 ShapeInfo 同时维护面积、x/y min/max 和右侧坐标；
- 当前形状结束时直接输出 `SumO / XMinO / XMaxO / YMinO / YMaxO`，
  也就是面积和 bbox；
- 主要存储来自两张 RAM：
  - `BlockRam18x2048`：行级标签缓存；
  - `BlockRam180x1024`：每个标签的 180-bit 形状信息；
- 标签计数器为 10 bit，最大 1023。

### 资源判断

- `180×1024 = 184,320 bit`，理想约 9 块 ERAM20K；
- `18×2048 = 36,864 bit`，理想约 2 块 ERAM20K；
- 粗算约 11 块 ERAM；
- 对 80×45 块图，可以大幅裁掉标签数和 ShapeInfo 位宽；例如只保留
  面积、bbox、运动量，并把标签宽度缩到 8 bit。

### 可借鉴

- 在像素流上直接得到面积和 bbox，不需要帧缓存或二次遍历；
- 标签表与形状表分开，便于按任务裁剪；
- 本工程可直接借“左侧/上方四邻域 + 合并写回”的控制思想。

### 局限

- `CCAL.v` 注释明确声明只做过少量仿真，复杂“回环/双分支”形状会漏统计；
- 没有完整并查集，复杂拓扑下写回链可能不收敛；
- 180-bit shape record 对当前 32 块 ERAM 预算偏重，必须裁剪；
- 代码不适合原样移植，适合作为结构验证和状态机参考。

## 3. tpss_ccl_8conn / fpga-autonomous-robot-car（FPGA，SystemVerilog）

- 项目：
  - [仓库](https://github.com/ylemiesa57/fpga-autonomous-robot-car)
  - [`ccl_8conn.sv`](https://github.com/ylemiesa57/fpga-autonomous-robot-car/blob/main/hdl/ccl_8conn.sv)
  - [`ccl_4conn.sv`](https://github.com/ylemiesa57/fpga-autonomous-robot-car/blob/main/hdl/ccl_4conn.sv)
  - [`ccl_calc.sv`](https://github.com/ylemiesa57/fpga-autonomous-robot-car/blob/main/hdl/ccl_calc.sv)
- 许可证：MIT。

### 实现逻辑

- 默认参数 `WIDTH=708, HEIGHT=146, LABEL_BITS=12, MAX_COMPONENTS=256`；
- 标准两遍扫描：
  - Pass 1：按 top-left/top/top-right/left 四邻居建立父指针；
  - Pass 2：沿父指针追到 root，再把 root 映射为连续标签并输出；
- 父指针存的是**像素地址**而不是紧凑标签，root 指向自身地址；
- 用 `GEN_BITS=2` 的 generation 字段处理帧间失效；
- 每像素有独立的 AXI-stream 输入输出、`m_axis_ready` 反压；
- `ccl_calc.sv` 只跟踪 `MAX_BLOBS=4` 个组件的面积和 x/y 累加，
  帧末除法得到质心。

### 资源判断

默认 ROI：

- 像素数 `708×146=103,368`；
- 父指针地址 `ceil(log2(103368))=17 bit`；
- 加 2-bit generation 后每项 19 bit；
- parent BRAM 约 `103368×19=1,963,992 bit`；
- 理想约 **96 块 ERAM20K**，还没计 root map 和行缓存。

这说明它是“用完整 parent image 换清晰两遍算法”的路线。即使把
`80×45=3600` 块作为输入，父指针表也约 `3600×14=50.4 Kbit`，
并受独立 RAM/宽度几何影响，至少需要数块 ERAM。

### 可借鉴

- 最标准的软件 CCL 转 RTL 结构，适合学习地址式 union-find；
- 先建立父指针，再统一压缩连续标签，结果确定性比简单 one-hop 写回好；
- 4-blob 上限和质心累加器的结构适合“只关心少数组件”的应用。

### 局限

- 两遍扫描必须有完整父指针图或保存整幅图；本工程直接做全分辨率不可行；
- 默认 ROI 的 parent BRAM 就接近 96 块 ERAM 的等效容量；
- 每次寻找 root 需要多次 BRAM 访问，不是稳定 1 pixel/cycle；
- 若只在 80×45 块图上使用，需要额外块图存储，并接受一帧延迟。

## 4. tthien22/Region-Growing-Verilog（区域生长参考，不建议移植）

- 项目：
  - [仓库](https://github.com/tthien22/Region-Growing-Verilog)
  - [`region.v`](https://github.com/tthien22/Region-Growing-Verilog/blob/main/region.v)
- 许可证：仓库未声明。

### 实现逻辑

- 示例图像 `273×182`，内存为 RGB 三维数组；
- 固定 seed `(150,90)`，取 seed 或当前像素颜色为阈值中心；
- 使用 RGB 三通道平方差之和与阈值的平方比较：
  `ΔR²+ΔG²+ΔB² < threshold²`；
- 使用 8 邻域 BFS 队列，维护 `processed` visited map；
- 将符合条件的邻居标为已访问、写入结果图并加入队列；
- 队列为空后把结果写成 hex 文件。

### 为什么不能直接当 FPGA RTL

- `initial` 中调用 `$readmemh`，结束调用 `$fopen/$fdisplay`；
- 使用完整输入图、输出图、visited 图和两个全图队列；
- 在单一时钟 `always` 中执行嵌套循环、阻塞赋值和动态队列索引；
- 行列参数与声明位宽不一致，且没有可综合的握手/存储接口；
- 因此它是一段仿真算法，不是综合后的流式硬件。

### 可借鉴

- 用上一帧手部质心作为 seed，在 `肤色 ∧ 运动` 块图上区域生长；
- 生长准则可以变成“块占用 + 运动分数 + 颜色差”；
- 只输出与 seed 连通的组件，天然避免选择最大团。

### 局限

- 需要 visited map 和队列。对本工程 80×45 块图，队列最坏约 3600 项，
  再加 visited、块图和种子/阈值状态；
- BFS 最坏访问量不可预测，不适合与每像素实时流水线强绑定；
- 若采用，建议放到帧消隐期，在 80×45 或更小的块图上跑，而不是全分辨率；
- 不能把该 Verilog 当可综合源码直接移植。

## 5. 另一个线索：niuwe/connect_domain_fpga

- [仓库](https://github.com/niuwe/connect_domain_fpga)
- [`CCL.v`](https://github.com/niuwe/connect_domain_fpga/blob/main/src/CCL.v)
- [`equivaluence_table.v`](https://github.com/niuwe/connect_domain_fpga/blob/main/src/equivaluence_table.v)

它使用：

- 1 pixel/cycle 流式输入；
- 上/上左/上右/左邻居的最小标签；
- 一个等价表做 union；
- 三个属性 RAM 累加面积、Σx、Σy；
- 帧末对最多 32 个结果做 root 合并和质心除法。

这个思路本身适合参考，但默认实现有明显工程问题：

- `WIDTH=10`、`HEIGH=10`，行标签 RAM 的 `DEPTH` 还硬编码为 10；
- `RAM_DEPTH=255` 但 `equivalence_table` 只例化 `MAX_LABELS=32`；
- 输出固定扫描 32 项；
- 等价表的 root chase 写法更像教学模型，未达到可直接上板的质量。

因此它适合看“单遍 8 邻域 + 并查集 + 属性 RMW”的数据流，不适合直接复用。

## 6. 对本工程的选型建议

### 首选：LinkRunCCA 思路，处理块图而不是全图像素

推荐输入层：

- 用现有 16×16 块坐标生成 `80×45` 的皮肤占用块图；
- 若手指/远端手太小，再考虑 `160×90` 的 8×8 块图。

处理层：

- 在帧末或消隐期，以 1 block/cycle 扫描块图；
- 用 run-length + linked list 维护 run；
- 只保存少量活动标签和 bbox；
- 对每个已完成组件输出 `bbox + area + motion_count`。

选择层：

- 锁定前：选运动量较高且通过面积/形状门的候选；
- 锁定后：选与上一帧手框中心距离最小、bbox 有重叠的候选；
- 连续 miss 2~3 帧再回全图重捕获。

应用层：

- 下一帧只在这只手 bbox 内保留肤色的全分辨率像素；
- 若需要更精确的外形，再生成一张 `80×45` 的 1-bit 接受块图；
- 不保存全分辨率 label map。

### 不推荐直接移植

- `tpss_ccl_8conn` 的完整父指针图：容量和随机访问代价都太高；
- Kryon 的 180-bit ShapeInfo 表：结构值得看，原尺寸太重；
- tthien22 的区域生长代码：仅仿真，不能当 RTL；
- niuwe 的默认实现：默认尺寸和等价表上限都只是教学配置。

### 区域生长是否值得

如果目标只是“从上一帧手部质心长出一整块手部区域”，区域生长在语义上
比全图多标签 CCL 更直接；但硬件上必须增加：

- visited map；
- BFS/LIFO 队列；
- 不定长邻域调度；
- 帧末的完成判定。

对 80×45 块图可行，但对当前 slice 余量不如 run-length CCL 友好。建议把
区域生长保留为“只在调试图/后续优化中验证”的备选，不作为第一版实现。
