## 0. 一句话总结

当前不是单一阈值问题，而是三层叠加：

1. **颜色判据对光照敏感**：白/自然光下手部色差和饱和度掉到窗边缘，黄光下手最稳但黄板也过门；
2. **锁定后纯肤色 + 窗口跟手 + AWB 全局漂移**：静止黄色背景会进入掩码，看起来“跟着手”；
3. **行带只选一条连续带**：脸、手、黄色木板连在一起时无法拆开，导致刀锋、下劈和背景误检。

当前阶段：行带截断修正已上板初测；下一步优先做**种子连通域 + 边缘阻挡 → 稳定刀锋轨迹**，
再处理运动选区/AWB 平滑、光照/肤色判据和诊断链路。

## 2. P0：不解决就无法验收

### P0-01　脸、手、黄色木板被并进同一条行带

- **状态**：已实现，待上板（2026-10-23）。
- **现象**：
  - 游戏模式/交付档下，脸也会被涂上掩码；
  - 手在脸下方时，刀锋出现在脸部左上方；
  - 视图 6 的行带框把脸、手、黄色物体一起框进去；
  - 下劈的 `Δy` 量的是脸顶，不是手顶。
- **已确认原因**：
  - `hand_band` 目前只输出**一条连续行带**；
  - 脸→脖子→手臂→手在垂直方向连续，整段被并成一条带；
  - `S_band_ymin` 因此是脸顶，M2 顶带和手势 `y_min` 都锚到脸。
- **建议修法**：
  1. ~~窄行拆带~~（2026-10-28 已移除：容易把手指一起排除）；
  2. **多候选**：同一帧允许产生多条候选带；
  3. **最近邻选择**：锁定后选离上一手框中心最近、半径 ≤256 px 的候选；未锁定用运动质心播种；
  4. **形状门保留**：面积、宽高、长宽比继续过滤细长手臂/扁平桌面；
  5. 可选：对“贴画面顶部且高度 >35%”的候选加距离惩罚，作为脸部辅助判据。
- **验收**：
  - 场景 C 下视图 6 的蓝框只框手，不框脸和黄色物体；
  - 下劈 20 次 ≥18 次；
  - 刀锋不再出现在脸左上；
  - `DBG` Q/R（行带 bbox）落在手上。
- **成本估计**：+150~250 LUT6，0 ERAM，0 DSP。
- **依赖**：P0-02 的粘指在它之后做，否则只解决 y、不解决 x。
- **本轮实现（2026-10-23）**：
  - `NARROW_ROWS=2`：连续 2 行窄于本带最大跨度的 40% 就结束当前带；
  - 触发行丢弃，下一有效行重新起带；
  - 每条关闭的带都作为候选进入最近邻比较，帧末仍开着的带继续参与选择；
  - 形状门未改。
  - 构建：slices **18158（85.59%）**、LUT6 16400、ERAM 76/108、DSP 8/40、
    final Setup **+837 ps**、Hold +20 ps，0 违例。
  - 待确认：场景 C 下视图 6 是否只框手；下劈是否改善；刀锋是否离开脸。
  - **2026-10-23 续（水平窗）**：逐拍 run 最近邻在 59 MHz 下时序不收敛，先采用
    **种子中心水平窗**：只统计种子左右 ±200 px 的掩码，先排除同一行里远离手的脸/木板。
    构建 slices **18225（85.90%）**、LUT6 16468、final Setup **+830 ps**、0 违例。

    截断，肤色行统计不再使用 ±200 px 水平窗，并删除 `NARROW_ROWS` 窄行拆带；运动统计

### P0-02　刀锋在手部上缘左右乱跳

- **状态**：粘指、M2 专用 7/8 和全局 7/8 A/B 版本均已构建，待上板验收。
- **现象**：
  - Build 2 已把刀锋从屏幕顶部拉回手部上缘；
  - 但刀锋仍在手部上缘左右跳，无法对准指尖。
- **原因**：
  - `S_tip` 取“顶带最上行、最左的掩码像素”；
  - 张开手时最上行同时压着多个指尖，最左者随手指微动切换。
- **建议修法（按优先级）**：
  1. **粘指**：顶带第一次出现掩码时，选离上一帧刀锋 x 最近的像素；连续 2 帧同列附近才确认；
  2. 当前指尖丢失时保持 1 帧，再选最近的可用像素；
  3. 如果粘指仍不够稳，再退化为“最上行掩码中点”或“顶带质心”。
- **验收**：
  - 静止手 10 s，刀锋 x 峰峰值 ≤4 px；
  - 慢移连续，不出现手指间瞬移；
  - 快移允许 1~2 帧滞后，不出现大跳。
- **成本估计**：+40~60 LUT6，少量 FF。
- **依赖**：P0-01 先保证行带在手上。
- **本轮实现（2026-10-26）**：
  - 仍先在顶带找第一个非空行，只在其后 `M2_TIP_EXTRA_ROWS=3` 行内找候选，
    避免把掌心和下方背景拉入；
  - 优先选择上一确认指尖 x 左右 `M2_TIP_STICK_X=32 px` 内的首个掩码像素；
  - 窗口内没有候选时记录整个顶部区域的第一个像素；若它与旧指尖相距较大，
    先保持旧指尖一帧，下一帧仍落在 `M2_TIP_CONFIRM_X=64 px` 内才确认换指；
  - 整个顶部区域一帧没有候选时保持上一指尖 1 帧，防止掩码单帧闪断直接打断
    `S_hit`；
  - 粘指窗口上下界在帧首寄存，像素扫描只做范围比较，避免新增长组合路径；
  - 构建 slices **18430（86.87%）**、LUT6 16722、ERAM 76/108、DSP 8/40、
    final Setup **+506 ps**、Hold **+20 ps**，0 违例；
  - 待确认：五指静止 x 峰峰值是否 ≤4 px、左右挥是否仍 ≥18/20、快速移动是否
    只有 1~2 帧滞后、下劈和场景 C 是否保持原基线。
- **本轮增量（2026-10-31）**：
  - 保留全局 `VOTE_MIN=5/8`，显示掩码、行带、质心和跟踪行为不变；
  - 新增 `M2_VOTE_MIN=7/8`，只用于 `S_m2_top` 的指尖/刀锋候选过滤，
    目标是去掉 bbox 顶部矩形背景中的低密度小团；
  - 构建：slices **17555（82.74%）**、LUT6 **16030**、FF **15415**、
    ERAM 76/108、DSP 8/40、feedthrough 6455、final Setup **+672 ps**、
    Hold +20 ps，0 违例、一次 PnR、bitgen 成功；
  - 待上板确认：静止手且矩形顶部有背景噪声时不再出现大幅 x 跳变，同时远处手、
    弱光边缘、左右快挥和切水果命中率不退化。
- **全局 7/8 A/B（2026-10-31）**：
  - 在 M2 专用 7/8 的基础上，将全局 `VOTE_MIN` 也从 5/8 提高到 7/8；

### P0-03　下劈基本识别不出来

- **状态**：部分解决。
- **现象**：
  - 左右手势准确率较高；
  - 下劈蓝条基本不出；
  - 顶部浅蓝条（未知方向）偶尔出现。
- **原因**：
  - Build 1：旧 ROI 把 `S_ymin` 钉在 ROI 顶边，手往下劈时顶边不动；
  - Build 2：改成行带 `y_min`，但脸/黄板进入行带后 `y_min` 又被拉到脸顶；
  - 不是单纯 `GEST_Y_TH=120` 太大；先降门限会把误触发一起放大。
- **建议修法**：
  1. 先完成 P0-01，让 `S_band_ymin` 真正是手顶；
  2. 再测 20 次下劈；
  3. 如果仍不足，再按顺序调：起点回退 2 帧、安静窗口改“最近 8 帧 ≥6 帧”、段最长 90 帧、最后才动 `GEST_Y_TH`。
- **验收**：
  - 下劈 20 次 ≥18 次；
  - 顶部浅蓝条（未知方向）明显减少；
  - 60 s 空闲误触发 ≤1。

### P0-04　锁定后静止黄色背景进入掩码，背景块跟手走

- **状态**：P0-04a/b 已实现并构建通过，待上板验收。
- **现象**：
  - 一开始静止黄色木板没有掩码（运动门过滤）；
  - 手掌出现并锁定后，黄板开始被涂；
  - 握拳/侧对镜头时手部掩码变小，背景掩码变多；
  - 手移动到哪里，背景上的掩码团就跟到哪里；
  - 手离开后，背景几乎充满掩码（混合光最明显）。
- **已确认原因**：
  - Build 1 后锁定态掩码切纯肤色、权重只认肤色分；运动分不再参与；
  - ROI/行带窗口跟着手移动，静止黄板不断被窗口“采样”；
  - AWB 逐帧全局，手的进入/形状变化改变整帧均值，背景色度跟着漂；
  - 手形越不标准，手部掩码越小，背景占比越大。
- **建议修法**：
  1. **运动选区**：给每条候选带累计运动像素数；手在动时优先运动分高的带；
  2. 锁定后仍用肤色补全手内部，但只在“运动选出的手带/行段”里补；
  3. 手停住后用最近邻/上一手框保持 N 帧，不因运动分 0 立刻丢；
  4. 与 P1-01 的 AWB 平滑/冻结配合；
  5. 最后再考虑“长时间无运动且形状不像手 → 释放锁定”的静态目标抑制。
- **验收**：
  - 手在黄色木板前移动，背景掩码不形成跟手大块；
  - 手离开后 N 帧内释放，不长期锁在黄板上；
  - 静止手仍能保持锁定，不被运动分误杀。
- **成本估计**：+100~200 LUT6，可能需要每带一个运动计数器和保持状态。
- **P0-04a 本轮实现（2026-10-24）**：
  - `hand_band` 增加 `I_motion`，统计水平窗内运动像素和全帧运动像素，帧首锁存；
  - 调参档 2（运动门开）借 DBG：P = 窗口内运动 >>4，Q = 全帧运动 >>6；
  - 构建 slices **18245（86.00%）**、LUT6 16516、ERAM 76/108、final Setup **+485 ps**、0 违例；
  - P0-04b 的释放/重播种尚未接线，本轮只提供运动证据。
- **P0-04b 本轮实现（2026-10-24）**：
  - 起始阈值用实测分界：窗口运动 `P < 0x0800`（32768 px）且全帧运动
    `Q >= 0x0200`（32768 px）；
  - 两个条件必须连续成立：手带仍有效且仍像手时累计 **60 帧**，否则累计
    **20 帧**；任一条件不成立立即清零，避免单帧噪声触发；
  - 超时后只清锁定、命中/丢失计数和速度，并把 ROI 恢复全帧；不把 bbox
    直接跳到运动区；
  - 下一帧走现有 `肤色∩运动` 捕获路径，由行带与形状门重新决定手框；
  - “仍像手”至少保持上一手带有效、面积 2000~120000、宽高均不超过 720，
    用于静止手仍成立而背景发生运动时延长保持；
  - 构建 slices **18322（86.36%）**、LUT6 16635、ERAM 76/108、DSP 8/40、
    final Setup **+669 ps**、Hold **+20 ps**，0 违例。
- **P0-04b 上板验收**：
  1. 手在窗口内运动、背景静止：不得误释放；
  2. 手和背景都静止：保持现有锁定，不被运动分误杀；
  3. 手离开、背景有运动：当前带不像手时约 20 帧（0.33 s）释放，像手时最多
     约 60 帧（1 s）释放；
  4. 窗口锁在干扰项、手在窗外运动：释放后确认能按 `肤色∩运动` 重新捕获手，
     而不是停留在干扰项；
  5. 释放过程 bbox 不得直接跳到全帧运动区；下一帧仍应经过行带/形状门。

### P0-05　白光/自然光下掩码覆盖不上手、闪一下就消失

- **状态**：未解决。
- **现象**：
  - 黄色辅助光：掩码最快、最完整；
  - 白色辅助光：手很难出掩码，出现也只是一闪、只覆盖一小块；
  - 自然光：与白光类似，偶尔多撑几帧；
  - 黄白混合：手能出，但背景黄板大量出掩码；
  - 手离开后背景充满掩码，黄光下反而不明显。
- **原因**：
  - 肤色判据是固定归一化色度窗 + `Y∈[32,200]` + `sat≥max(Y/8,12)`；
  - 白光把 R/G/B 拉近，`d2=R−Y`、`|d1|=Y−B` 和饱和度变小，手掉到窗边缘；
  - 黄光放大暖色差和饱和度，手容易过门，但黄板也容易过；
  - 自然光 Y 低、噪声大，`Y_MIN` 和绝对饱和度下限杀暗部；
  - AWB 逐帧全局，进一步改变工作点。
- **曝光事实**：
  - `A=0x0F96=3990`，`ae_set.v` 写死 `r_ae_set < 3990`；
  - `G=0x0059=89`，模拟增益上限也是 89；
  - **AE/AG 都已经到当前工程上限**，继续按 K3 不会更大；
  - 曝光单位是 1/2 行；sensor 理论上限为 `2×行长−10`，要再高只能改行长、降帧率、开数字增益或改善灯光。
- **建议修法**：
  1. 演示优先用**黄色/暖色柔光 + 扩散**，避免白色冷光；这是最省力的稳定方案；
  2. 软件上用**运动选区**（P0-04）保证手在动时能出区域；
  3. AWB 加时间平滑/锁定（P1-01），避免手进入/离开时全局色偏跳变；
  4. 如需白光鲁棒，考虑“严格核心 + 宽松光晕”的两级肤色模型：运动种子附近用宽松判据补手，远处仍用严格判据；
  5. **不要全局放宽肤色阈值**，否则黄色木板会更脏。
- **验收**：
  - 白光/自然光下，手在动时掩码覆盖率明显提升；
  - 背景误检不因放宽阈值而失控；
  - 黄光不再“最好但唯一可用”。

## 3. P1：影响调试效率和稳定性

### P1-01　AWB 逐帧全局、无时间平滑

- **现象**：同一块黄板，手形不同时红色多少不同；手离开后背景突然充满掩码。
- **原因**：AWB 每帧用整帧 R/G/B 均值算 `G/R`、`G/B`，没有 IIR/保持；手的出现改变全局均值。
- **建议**：AWB 增益做慢速 IIR（例如每帧 1/8）；或锁定手期间冻结/慢走，释放后恢复。
- **验收**：手进入/离开时，背景像素的色度不出现大跳；掩码不整片闪现。

### P1-02　误锁静态大木板后难以释放并重播种

- **现象**：
  - 误锁到大面积静止木板或脸以后，即使旁边有手在运动，也可能不释放；
  - P0-04b 的释放/重播种在现场没有按预期把手重新锁回来；
  - 当前判断为不影响主验收链路，但会影响复杂背景下的恢复能力。
- **可能原因**：
  - `S_band_handlike` 只要求手带有效、面积 2000~120000、宽高不超过 720；
    大面积木板很容易满足，于是低置信度保持时间从 20 帧延长到 60 帧；
  - `P` 统计的是种子运动证据窗 `±MOTION_WIN` 内的全部运动，不是当前锁定 bbox
    内部的运动；手只要进入该窗，`P` 可能重新升高，低置信度条件立即清零；
  - `S_hit` 在静态木板纯肤色下仍可能成立，因此“错误目标仍命中”与
    “周围有手在运动”可以长期同时存在。
- **建议修法**：
  1. 统计“当前 hand band bbox 内运动”，不再用整个水平窗运动代替目标运动；
  2. 给“像手”条件增加矩形度/占用率/时序稳定性，避免大木板通过；
  3. 手带像手只用于延长保持，不豁免最终释放；用内部运动为零和外部运动
     存在共同压低置信度；
  4. 释放后保留正常 `肤色∩运动` 重播种，并记录当前 bbox 与新种子距离，
     便于上板判断是否锁回手。
- **验收**：静态木板/脸被误锁后，邻近手持续运动应在约定帧数内释放并锁回手。

### P1-03　已锁手部拉远后突然丢锁，挥手仅短暂重锁

- **状态**：2026-10-26 新发现，未解决。
- **现象**：
  - 已经稳定锁定手部后，手与镜头距离增大到一定程度，手部掩码会突然消失；
  - 在同一距离重新挥手可以短暂重新锁定并出现掩码，但几帧到几十帧后再次消失；
  - `0005` 原始肤色视图在更远距离仍能覆盖手部，说明不是第一级肤色判据先失效。
- **已排除**：
  - 不能归因于原始肤色缺失；`0005` 已证明更远处仍有肤色；
  - 不能归因于捕获态运动门；该问题发生在已经锁定后，锁定态使用纯肤色权重。
- **可能原因（按优先级）**：
  1. `hand_band` 的绝对形状门随距离失效：整手投影变小时，`area≥2000`、
     `width/height≥60`、行 `span≥40` 或 `count≥24` 先越界；
  2. 行带失效后 `S_band_valid=0`，显示掩码立即消失；随后 M2 失去顶带，
     `S_tip_ok=0` 让 `S_hit=0`，连续 `HOLD_FRAMES=5` 帧后正式解锁；
  3. 锁定态纯肤色 `Σw` 仍可能低于 `MIN_WSUM_HOLD=1200`；
  4. P0-04b 低置信度释放：背景有运动且当前带不再被判定为“像手”时，
     20/60 帧后会强制释放；
  5. 挥手时捕获权重能短暂产生质心和行带，但锁定切回纯肤色后手框缩回，
     若真实尺寸低于形状门，就只能维持短暂几帧。
- **建议诊断**：
  - 在同一失败距离比较 `0001` 与 `0003`；若两者都丢锁，可排除运动门；
  - 用 `0006` 观察肤色仍存在时行带 bbox 是否先消失；
  - 后续需要把 `S_band_valid`、`S_band_area`、行带宽高、`S_cent_valid`、
    `S_wsum_h`、`S_tip_ok`、`S_locked`、`S_miss_cnt` 暴露到调试通道；
  - 不要用 `0005` 的肤色可见性直接判断行带、指尖和 `Σw` 是否通过。
- **候选修法**：
  1. 给锁定态增加小目标形状门或远处滞回，避免真实手框刚低于 2000 像素就立即判无效；
  2. 行带短暂无效时保持上一 bbox 多帧，同时只暂停显示，不立即破坏指尖链；
  3. 将 `S_tip_ok` 与行带有效性解耦，允许使用上一有效顶带短暂保持；
  4. MIN_WSUM 和形状门后续按距离/面积做分档，但必须先通过诊断字段确认卡点。

### P1-04　条件水平窗（已关闭）

- **状态**：2026-10-28 关闭肤色侧水平窗；`MOTION_WIN` 只保留给运动证据。
- **原因**：`H_WIN=200` 会直接截断靠窗边的手指，和“完整手部掩码”的目标冲突。
- **后续**：目标身份由种子连通域选择，不再用水平窗硬裁切肤色行统计。

### P1-05　调试图和识别配置耦合

- **现象**：
  - `W 08 0005` = 档 5，运动门关；
  - `W 08 000B` = 档 11，运动门关 + 松门限；
  - `W 08 0006` = 档 6，运动门也关；
  - `W 08 0001` 是交付视图，重复写同值可能不提交。
- **影响**：无法在“保持 cfg 1 识别”的前提下只看原始肤色/提示条/行带；`000B` 的误触发不能代表交付档。
- **建议**：
  - 增加独立 `diag_en` + `diag_view` 寄存器（C 段 0xC0/0xC1 或独立视图寄存器），不改 `recog_algo`；
  - 或做编译期 debug view override（保留 cfg 1，强制视图 5/6/条）；
  - 交付档仍保持“只有 cfg 1 叠加”。
- **验收**：切视图时 `K` 的 algo 不变，识别行为不变。

### P1-06　`W 08 0001` 重复写不重新提交

- **现象**：发 `0001` 有时画面不切；发 `0005` 可以。
- **原因**：`mode_sync` 只在 26 位请求字变化时转发；`recog_algo` 已经是 1 时，再写 1 是空操作。
- **workaround**：`W 08 0000` → `W 08 0001`，或 `W 08 0005` → `W 08 0001`。
- **建议**：给 `param_ctrl` 加写序号/翻转位，每次 UART 写都强制提交；或独立视图寄存器。

### P1-07　`DBG` 的 P/Q/R 不可信

- **现象**：多数行 `P/Q/R=0000`，偶尔跳到 `0004/22CE/034E`，与屏幕连续掩码不一致。
- **影响**：无法用 P/Q/R 做客观验收。
- **建议**：
  - 先验证 `O_status_toggle` 与像素域整包捕获是否每帧更新；
  - 再考虑把 `S_band_*`、`S_tip`、`S_locked`、`Σw` 暴露到 DBG；
  - 在字段可信之前，验收以画面 + 提示条 + 游戏 `hit_cnt` 为准。

### P1-08　`K` 字段解码容易误读

- `S_mode_dbg = {4'h0, algo, game, display}`；
- `K=0100` = `algo=1, game=0, display=RAW`，不是 `algo=0`；
- 需要在 README/调试文档里固定这张表，避免再次误判。

### P1-09　静态启动需要先动一下手

- 未锁定用运动质心播种；手一开始完全静止时不会首次锁定。
- 当前接受“开机后先动一下手”；如果后续需要静止启动，再加“无运动 N 秒回退最大带”的兜底。

### P1-10　资源 86.87%，后续改动余量紧

- 粘指：slices 18430/21216（86.87%）、LUT6 16722、WNS +506 ps；
- 运动权重阶段一：slices 18302/21216（86.27%）、LUT6 16573、WNS +391 ps；
- P0-04b：slices 18322/21216（86.36%）、LUT6 16635、WNS +669 ps；
- 85% 舒适线已超过，90% 红线内；

### P1-11　手距离镜头较远时难以播种和锁定

- **现象**：手离镜头较远时，档 5 的原始肤色掩码仍能覆盖手，但正常跟踪难以
  产生或保持锁定。
- **结论**：肤色颜色判据本身基本与距离无关；距离通过目标投影面积缩小，
  间接影响运动播种、行带形状门和连续命中条件。
- **主要卡点（按处理顺序）**：
  1. 未锁定时种子来自 `肤色∩运动`；远手像素少、帧间位移也小，
     `S_cent_valid` 要求 `Σw ≥ 2000`，容易先在这里失效；
  2. `hand_band` 要求每行 `count ≥ 24`、`span ≥ 40`，整带面积
     `≥ 2000`、宽高均 `≥ 60`；远手会先掉出跨度和形状门；
  3. `S_hit` 在捕获态同样要求 `Σw ≥ 2000`，且 `LOCK_FRAMES=3`，
     远手只能间歇命中时无法连续锁 3 帧；
  4. 种子正确时 `SEARCH_R=256` 和 `H_WIN=200` 通常不是首要卡点；
     只有种子已被脸部/背景拉偏时才可能成为限制。
- **建议诊断**：先用档 2 的 P/Q 看远手是否产生足够运动；再把行带 bbox、
  `S_cent_valid`、`Σw`、`S_band_area` 暴露到 DBG，区分是“没有种子”还是
  “有种子但行带/形状门失败”，不要直接同时放宽全部阈值。
- **阶段一实现（2026-10-24）**：
  - 捕获态不再重新做逐像素运动分；`S_motion_mask` 中已确认运动的 16×16 块内，
    肤色像素直接取得自己的皮肤分作为权重，块外权重为 0；
  - 锁定态仍恒用纯肤色权重，`MIN_WSUM`、`MIN_WSUM_HOLD`、`LOCK_FRAMES`、
    运动块阈值和行带形状门均未修改；
  - 构建 slices **18302（86.27%）**、LUT6 16573、ERAM 76/108、DSP 8/40、
    final Setup **+391 ps**、Hold **+20 ps**，0 违例；
  - 待上板验证：远手在 0002 下能否首次锁定、静态黄色木板是否仍被排除、
    近锁后拉远是否保持、场景 C 是否出现新的背景粘连。

## 4. P2：已解决或已闭环

### P2-01　掩码 1 秒出现/消失、刀锋冻结后乱跳、斩击发不出

- **根因**：锁定后软权重仍乘运动分，手停住 `Σw` 归零；
- **修复**：Build 1 锁定后权重只认肤色分，质心有效门限与命中判据共用 2000/1200 滞回；
- **结果**：10 s 静止掩码/黄十字连续，1 秒循环消失。

### P2-02　Build 2 第一次 PnR -850 ps

- **根因**：`r_awb_g → 行有效 → best_dist.cea` 长组合路径；
- **修复**：行摘要寄存器 `q_*`，行有效性移到寄存器之后判；
- **结果**：final Setup +700 ps，0 违例。

### P2-03　提前做 Build 2、没等 Build 1 上板

- 已回到 Build 1 验证，Build 2 完整保留在 `feat/gesture-recog-optimize` 和 tag `gesture-build2-20261021`；
- 后续严格按“一次只改一个变量 + 上板验证 + 再下一个”推进。

### P2-04　参考项目并不能直接解决脸

- **Xu-Zihao-cqu/fpga-vision-gesture-controller**：固定右半屏 ROI + 最大行带 + 形状门，没有显式人脸检测；脸不在 ROI 是取景假设。
- **jorgetomaylla/FPGA-Hand-Tracking-with-Video-Enhancement**：降采样连通域/多 blob，没有脸/手语义；连在一起仍是一个 blob。
- **结论**：可以借行带/形状/扫描线思想，不能指望“最大连续行带”自动挡脸；
  当前优先做种子连通域，并用运动种子和强边缘阻挡区分粘连目标。

## 6. 上板验收命令与判读

串口 115200-8-N-1、CR/LF；不要按 KEY4（会重置 `recog_algo`）。

```text
W 08 0000      # 先清零，强制下一次提交
W 08 0001      # 交付视图：红掩码 + 黄十字
W 08 0005      # 只看原始肤色（注意：会切到档 5，运动门关）
W 08 000B      # 档 11：松手势门限 + 三色提示条（运动门关）
W 08 000A      # 档 10：正常手势门限 + 三色提示条
W 08 0006      # 行带/融合诊断视图（会切到档 6，只适合短时目视）
```

提示条：

- 左侧红条 = 左挥；
- 右侧绿条 = 右挥；
- 底部蓝条 = 下劈；
- 顶部浅蓝/青条 = 方向不明确（看到了动作，但不够左/右/下）。

`DBG`：

- `K` = `{0, algo, game, display}`；
- 交付档 Q/R 现在是行带 bbox（Build 2），但 P/Q/R 目前仍有捕获不可信的问题，需先以画面为准。
