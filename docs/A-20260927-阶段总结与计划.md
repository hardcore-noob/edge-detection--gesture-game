## 2. 已经查清的结论

### 2.1 准星"不跟手"（已解决）
根因：运动门用帧差时只给"轮廓"，`Σw` 又小、又跟速度成正比 → 命中门 `Σw ≥ MIN_WSUM` 时断时续 →
位置整帧冻结 + 速度清零 → "手在动、准星不动"。
对策（已生效）：**软权重 + 只在 ROI 内投票 + `DEADBAND=2` + `MIN_WSUM=2000`**。用户确认"准星还算可以"。

### 2.2 "灯照亮的桌面一直高亮"（走了三段弯路，最终定位）
1. 先当"补偿/阈值"问题 → step17（相对门限 + 背景自愈 + 采样加密）→ **上板无效**。
2. 再当"16×16 背景模型分辨率下限"问题 → step18（帧差 + 块级锁存）。
3. step19 用**运行时预设档做归因实验**：
   - **档 8（只肤色，运动门恒开）：桌面仍然亮** → 桌面是**肤色门**收进来的；
   - **档 9（只肤色 + d2 收严 7..63 + 尺寸门 480）：桌面完全不亮，但手也很难亮。**
   - **推论：背景模型 / 运动门 / 帧差 / 锁存，与"桌面高亮"无关，可整段摘掉。**

### 2.3 参考工程（anlu：2024 安路赛道国二，Hu 不变矩手势识别）
- **肤色判据和我们本来就是同一套**标准 CbCr 矩形：他们 `Cb∈(77,127) && Cr∈(133,173)`，
  换算成我们的 `d1=B−Y / d2=R−Y` 是 `d1∈[−100,−5] / d2∈[7,63]`；我们放宽成 `d2∈[0,70]`。
- 他们整条链路：**肤色二值 → Sobel 求轮廓 → 3×3 腐蚀 → 3×3 膨胀 → 面积÷周长比 + Hu 矩 → 六模板最近邻**。
  **没有背景模型、没有运动检测**（固定 300×300 框）。即"肤色负责在哪，形状负责是什么"。
- 可直接借用：Cr 收严、RGB→YCbCr 定点系数、3×3 中值滤波、2D 形态学、面积/周长比、每级可选显示的调试习惯。
- 不能借用：OV2640 I2C / SDRAM 控制器 / VGA 时序 / 800×600 与固定框坐标。

### 2.4 顺手修掉的一个真 bug
背景预取地址 `(S_blk_x==79) ? S_row_base : S_addr_cur+1` 在每块行最后一个块**回卷到本行首块**，
于是"每块行的第一个块（图像最左 16 像素）"用的是**上一行首块**的背景 → 最左边一条 16 像素永久竖线
（很可能就是最早看到的"两条竖线"之一）。已改成扫描顺序的下一个块。

## 3. 后续计划（压到 3 步，只有 1 个决策点）

### 第 1 步：拆杠杆（**一次编译**，约 5 分钟）
档 9 同时动了三个旋钮，必须拆开。新增三个"只动一个旋钮"的档：

| 档 | 只动这一个 | 其余保持宽松 |
|---|---|---|
| 8 | 全宽松（基准，已有） | — |
| **10** | d2 下限 0 → 7（要求"更暖"） | 上限 70、尺寸 720 |
| **11** | d2 上限 70 → 63（拒绝过饱和偏红） | 下限 0、尺寸 720 |
| **12** | 尺寸门 720 → 480 | 色度全宽松 |

**唯一验收判据：有没有哪一个单档做到「桌面不亮 + 手亮」。**

### 第 2 步：按第 1 步结果二选一
- **有单档可行** → 收参数收工，再加一条"阈值随亮度自适应"（暗环境手不亮，多半是绝对阈值随光照按比例缩水）。
  **M1 到此为止。**
- **三个单档都不行**（桌面和手的色度就是重叠的）→ 换判据：**相对背景色度** ——
  不判"这个像素像不像皮肤"，改判"**这个像素比它所在位置的背景更暖**"。
  桌面与自己的背景色度相同 → 差值 0 → 天然不过；手进来才产生差值 → 过。
  顺带解决"换环境 / 换白平衡"。成本：每块多存 2 个色度字节（+4 块 ERAM），复用现成的块采样通路。

### 第 3 步：删掉没用的那一大段
确认运动门无用后，把 **背景模型 / 自愈 / 帧差 / 锁存** 整段摘掉（省 3 块 ERAM + 几百 LUT），
资源留给 M2（Hu 矩 + 模板分类）。

## 7. 第 1 步已落地（2026-09-27 续）—— 档 10/11/12 + 准星同源

用户答了 §5 那个待确认的问题：**档 8（桌面亮着）时准星会被桌面拽走**。
于是本节判据从"桌面不亮 + 手亮"扩展为**「桌面不亮 + 准星不被拽 + 手亮」**，
并且必须先修两个被漏掉的地方：

- **准星与掩码不同源**：掩码走 `d1/d2` 矩形，准星走"暖色占优 + 饱和"的软权重。
  档 9 的 d2 收严**只接进了掩码**，准星一路完全没变 —— 所以档 9 下桌面不亮，准星照样被拽。
- **档 9 的尺寸门在 `SOFT_TRACK=1` 下是死代码**（`S_size_ok` 无人消费）。
  若照原计划让档 12"只改尺寸门"，会得到一个空档和一个错误结论。

本版改动（`isp/recog_top.v`）：档 10 = 只收 d2 下限；档 11 = 只收 d2 上限；档 12 = 只收尺寸上限
（并把它接进软权重命中判定）；准星肤色分改成"先在肤色矩形内，再算暖色+饱和"。
档 8 与上一版逐位一致，所以基线可复现、对比依然是单变量。
