## 5. 上板调优历史（用户反馈 → 改动）

1. "手变红了" → 掩码工作正常（肤色∩运动命中手）。
2. "画面暗、觉得分辨率不高" → 不是叠加造成的；曝光是手动的、掉电不保留，按 **KEY3** 加曝光，
   `DBG:` 的 `A=` 会变。
3. "准星太小" → 半臂长 5→10、线宽 1→3 像素。
4. "唇膏也被检测到" → 加目标门控（尺寸≥60×60、宽高比≤3）。
5. "准星跟不上手" → α 1/4→1/2、β 1/16→1/8，ROI 余量 64→160（原来手快移会滑出窗口被判丢失）。
6. "准星不在框中心" → 撤销"取包围盒上缘"的尝试，锚点回到包围盒中心。
7. "框很乱、挤满屏幕" → 绿框整个撤掉，只留指针 + 掩码高亮；框改画紧贴包围盒（后被撤掉）。
8. "颜色完全消失" → 掩码高亮从"G/B 减半"改成"**红通道拉满 + G/B 减半**"。
9. "按键用不了" → 见第 6 节（KEY4 需要跨域接线，先由 C 实现）。

## 6. KEY4 门控的来龙去脉（重要）

- **为什么原来用不了**：KEY4 → `I_button[3]`(C7) → `key_event`/`param_ctrl`（**像素域**）只写
  `game_mode`；A 线的识别在 **CSI 域**，两域之间当时只有 `mode_sync`（只提交 display_mode/edge_th）
  和 CTRL_SYNC 测试字，**没有任何随 KEY4 变化的信号**。
- 我先后试过：① 用 `display_mode`(KEY1/EDGE) 当开关（被用户否——KEY1 归边缘检测，合并会冲突）；
  ② 自己改 `design_top_wrapper.v` 两行把 game_mode 塞进提交字（被用户否——不能动 C 的文件，已 `git restore` 回退）。
- **最终由 C 解决**：`f55ee2b` 把提交字扩成 **26 位**并带进 CSI 域，契约：
  `S_mode_word[15:12] = recog_algo`（0=停/1=手势）、`[11:8] = game_mode`。
- A 线现在的接法：`isp_top` 里 `S_ovl_en = MASK_PREVIEW | (I_mode_committed[15:12]==4'd1)`
  —— **完全按 C 的契约**，不再有任何 A 线自造的跨域端口。

## 9. 经验教训

- **中文路径是这个项目最大的隐藏雷**：TD 安装、工程路径、烧录文件路径任何一处带中文都会炸，
  而且报错信息往往指向别处（`PRG-8000`/`PRG-8002`）。
- **乘法会悄悄吃 DSP**：长宽比判据一开始用 `*` 写，TD 直接加了 2 个 DSP（8→10），
  违反 A 线"DSP 0"的配额；改成移位加法后回到 8。**A 线任何新逻辑都要复查 DSP 计数**。
- **同一份逻辑 WNS 会因布局落点差 3~4 倍**，别拿单次数字下结论，门禁只看"这一版过没过"。
- **没有仿真器**：所有验证靠上板，所以改动要小步、每次上板都要留数据（`DBG:` 日志 + 构建数字）。
- `apply_patch` 走不了 junction 路径；新增行的换行符是 LF、仓库其余是 CRLF（提交时 git 会归一）。
